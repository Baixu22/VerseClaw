## Verse Claw 本地多 agent 推理架构与优化方向 (2026-07-07)

- 现状: Electron Main 仅拉起**单** OpenClaw Gateway 进程 (electron/gateway/*, 端口 18789)，所有 agent 推理汇聚到此单通道。
- 本地模型: openclaw_runtime/extensions/lmstudio 等扩展把 chat completion 转发到本地 LM Studio/Ollama HTTP 服务；GPU 推理发生在模型服务进程内，Gateway 不碰 GPU。多 agent 共享同一 GPU 后端。
- 多 agent 协作: src/components/agents/SubagentRunnerPanel.tsx 用 explorer/reviewer/tester/compare 预设派生多个 worker run，全部打到同一本地模型服务。
- 瓶颈: 本地模型服务的并发上限 → 多 agent 排队。GPU 仅对本地推理有效；云端 API 场景客户端 GPU 无效。
- 优化优先级(本地): ① orchestrator 并发信号量 > ② prompt-cache 复用 > ④ 多模型并行+量化+并发调参 > ③ 结果/embedding 缓存 > ⑤ 错峰派发+流式早退 > ⑥ 上下文/显存纪律 > ⑦ 渲染/多窗口(共享GW socket、背景节流、WebGL、虚拟化、吞吐遥测)。
- 多窗口当前未真正落地: electron/main/window.ts 仅做单窗口状态持久化，window-api.ts 只操作 mainWindow。
