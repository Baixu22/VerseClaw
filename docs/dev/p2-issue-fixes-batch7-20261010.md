## Correction to the first version of this batch (same change set, never pushed)

The first candidate deleted `public/lobe-icons/` outright on the issue's
"unreferenced" premise and added a test asserting the directory stays absent.
That premise is false, and the deletion was a user-visible regression:

- `src/pages/Chat/ChatInput.tsx:4779` wraps `MaterialFileTypeIcon` in
  `LobeConfigProvider` with `proxy: 'custom'` and
  `customCdnFn: () => new URL('./lobe-icons', window.location.href).toString()`.
- `@lobehub/ui/es/MaterialFileTypeIcon/MaterialFileTypeIcon.mjs` calls
  `useCdnFn()({ path: 'assets', pkg: '@lobehub/assets-fileicon', version: '1.0.0' })`
  and renders `<Img src={iconUrl}>`, where `getIconUrlByName()` builds
  `` `${iconsUrl}/${iconName}.svg` ``.
- So a non-image attachment whose filename maps to a known icon (`.ts`, `.json`,
  `.md`, …) requests `/lobe-icons/<iconName>.svg`; `dist/lobe-icons/typescript.svg`
  in the built app confirms that path is served from `public/` in production.

Deleting the directory would have broken every such icon. The measured failure
mode is not a clean 404: with the directory parked, the Vite dev server answers
`/lobe-icons/typescript.svg` with **HTTP 200 and `content-type: text/html`**
(8,930 bytes of `index.html` from the SPA fallback), so the `<img>` receives
HTML instead of an SVG. The change set now keeps the URL and the served bytes
identical while removing the tracked duplicate, which is what the issue actually
asked for.

## Changes

- **#65**: every `harness/specs/tasks/**/*.md` file now declares
  `lifecycleStatus: active | completed | archived`. Historical specs are
  `archived`; this batch spec is `active`. `scripts/check-spec-lifecycle.mjs`
  and the harness CI entry point fail closed on missing or invalid values.
- **#66**: `docs/dev/repository-layout.md` defines top-level ownership and the
  allowed evidence roots; `packages/README.md` and `packages/vtoken/README.md`
  classify the Python/uv sidecar; and the former root design note moved to
  `docs/dev/send-button-states-design.md`.
- **#67**: `openclaw_runtime/UPSTREAM.md` records the upstream URL, vendored
  version, npm compatibility-bundle role, local-fork/sync policy and tracked
  WASM rationale. `PRUNE-MANIFEST.json` is marked superseded and version-aligned
  with the runtime package.
- **#71**: `docs/README.md` indexes every top-level docs markdown file and all
  four README locales link the index.
- **#72**: tracked files larger than 100 KiB are SHA256-grouped by
  `scripts/check-duplicate-assets.mjs`; every reviewed duplicate group is in
  `scripts/duplicate-assets-allowlist.json` with an explicit retention reason.
- **#82**: the renderer's file-type icons are no longer vendored in Git. The
  `public/lobe-icons/` tree (910 SVGs) was a byte-identical copy of the
  MIT-licensed `@lobehub/assets-fileicon` dependency that `package.json` already
  declares. It is now generated by `scripts/sync-lobe-icons.mjs` into a
  `.gitignore`d directory, wired into `predev`, `predev:mock` and
  `prebuild:vite`, with `PROVENANCE.json` recording package/version/licence and
  per-file digests. `tests/unit/lobe-icons-assets.test.ts` pins the generated
  bytes to the dependency, keeps the tree out of `git ls-files`, and keeps the
  renderer's `/lobe-icons` CDN contract aligned with the directory name.
- **#91**: runtime `deadcode:unused-files` is part of the runtime source gate,
  and the historical prune manifest no longer presents itself as current.
- **#94**: runtime import-cycle and deprecated-API checks run in CI; the
  upstream 500-line rule now runs in baseline mode
  (`openclaw_runtime/scripts/ts-max-loc-baseline.json`) and fails on new or grown
  offenders.
