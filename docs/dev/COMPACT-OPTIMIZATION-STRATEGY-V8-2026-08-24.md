# Compact 优化策略 v8：从"防虚构"到"下游任务驱动"（2026-08-24）

状态：策略提案（未开工）。前置状态：v7 三阶段验收全绿（见 `reports/context-compression/P6-TF0074-V7-COMBINED-ACCEPTANCE-2026-08-24.md`）。

## 0. 战略判断

v7 完成的是**信任地基**：证据接地、零虚构、可审计、多阶段验收。这是我们的护城河——工业界（Claude Code / Codex CLI 的纯 LLM 摘要）没有任何等价保证。

但压缩器本体仍是**手工启发式**（正则抽取 + 固定模板）——ACON（ICML 2026）明确批评的 "brittle heuristics"。本周的修复过程就是证明：10+ 个缺陷全靠人肉逐个补丁。

优化方向一句话：**保留确定性证据骨架，在其上叠加学习型组件，把优化目标从代理指标换成下游任务成功率**。不是替换，是杂交。

核心纪律：**先有真度量，再做优化**——否则就是在代理指标上继续过拟合（本轮已亲身验证这个陷阱）。

## 2. 方案架构（四阶段）

### Phase 0：下游真度量（Handoff Benchmark）——一切优化的前提
**问题**：现在的 continuation 是代理指标（从候选里选动作），不是真任务完成度。在它上面优化 = 对代理过拟合。

**做法**：
- 把 continuation 升级为真实接手实验：agent 只拿压缩摘要 → 实际执行后续任务 → 度量：任务完成？重复已完成工作？矛盾动作？状态判断正确率？
- 语料：现有 30 样本中挑 10-15 个有明确"后续可执行动作"的（R4/R23/R25 类失败修复任务、R10-R17 类待执行目标）
- 度量协议：双盲（接手 agent 不知道原始 transcript）、ground truth 由 transcript 人工标注（每样本 1 个正确终态 + 1 个正确下一动作）
- 成本：每样本 1 次 agent run（小模型即可，qwen-flash 级）

**产出**：`handoff-success-rate`、`repeat-work-rate`、`contradiction-rate`、`state-accuracy` 四个真指标，成为后续所有优化的唯一裁决者。

### Phase 1：接地式 LLM 抽取器（混合架构）
**问题**：正则抽取器脆弱（本周 10+ 补丁为证）、模式外的内容静默丢失（R21 mission_loop 案）。

**做法**：
- 小模型（qwen-flash / qwen3-8b 级）做候选事实抽取，**强制输出溯源**：每条事实必须附带 `file:line` + 原文引用片段
- **确定性验证器**（复用现有设施）：引用片段不是源文逐字子串 → 拒绝该事实（fail-closed）→ 零虚构保证不变
- 现有正则抽取器保留为**交叉校验源**：双抽取器一致的事实高置信，不一致的进入人工/裁决队列
- 摘要生成：从"模板填充"升级为"接地生成"——生成器只能引用已验证事实池，生成后由验证器二次核查

**产出**：抽取召回率提升（模式外内容不再静默丢失）、虚构率保持 0、抽取器从"规则集"变成"可审计的候选生成器"。

### Phase 2：ACON 式自动准则精化闭环
**问题**：本周的修复循环（失败分析 → 改规则 → 复验）是人肉的，带宽太低。

**做法**（ACON 的手动版 → 自动版）：
- 循环：压缩 → Phase 0 度量 → LLM 失败分析（对失败样本归因）→ 提出准则修改 → **冻结 holdout 上验证** → 接受/拒绝
- 准则 = 抽取器/生成器的结构化 prompt，版本化管理，每次变更附消融证据
- 语料三分：**回归集**（现有 30，只回归不优化）/ **优化集**（新采集，可迭代）/ **冻结 holdout**（只终评，禁止回看）——从制度上杜绝过拟合
- 每轮循环产出一份 `optimization-round-N.md`：失败归因、准则 diff、holdout 前后对比

**产出**：压缩质量的持续自动改进；人从"改规则"退到"审准则变更"。

### Phase 3：自适应压缩策略
**问题**：固定模板 + 固定触发阈值不适应任务形态差异。

**做法**：
- **任务形态感知预算**：调试类（保失败链细节）、探索类（保发现清单）、多任务串行类（保任务边界+追踪态）、交接类（保 next action 精度）——形态分类器 + 分节预算表；理论依据用 Rate-Distortion 论文
- **评估侧对齐 COMPINT**：schema-free 阶段升级为 side-constraint loss 评估（约束保持率：不可违反的用户约束在压缩后的存活率）
- **触发时机**：从固定容量阈值改为"信息密度衰减检测"（观察窗口内新增信息的边际价值低于阈值时触发）

### Phase 4：蒸馏（成本驱动，可选）
- 把 Phase 2 优化后的压缩器蒸馏到本地小模型（ACON 证明小模型经优化可胜任，且他们的增益最高 46%）
- 前提：Phase 2 收敛且调用成本成为痛点

## 4. 风险与诚实声明

1. **语料多样性未解决**：全部优化都还是单用户/单任务族语料。Phase 0 的 holdout 必须引入新类型语料（不同项目/语言/任务形态），否则闭环会自嗨。
2. **judge 依赖**：Phase 0 的真度量用任务完成度，绕开了 judge 偏差问题——这也是它必须排第一的原因。
3. **成本**：Phase 0 每轮 ~15 agent runs；Phase 2 每轮循环 = 压缩 30-50 样本 + 接手评估 + 失败分析，小模型为主的话每轮 < ¥10。
4. **不承诺**：这套方案提升的是"证据接地的压缩质量"；模型本身的长程推理能力不在优化范围内。
