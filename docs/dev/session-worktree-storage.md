# 会话、Git 工作树与存储管理

## 调研与设计依据

本次通过 VerseSearch 的 AnySearch 路线检索并读取官方资料：

- [Codex Worktrees](https://developers.openai.com/codex/app/worktrees)：在输入区下方选择执行环境，以独立检出目录隔离并行会话；工作树与会话关联。
- [Claude Code Desktop](https://code.claude.com/docs/en/desktop#run-a-session-in-its-own-worktree)：Code 会话保留独立历史与项目目录，从输入区选择本地目录或工作树。
- [Git worktree](https://git-scm.com/docs/git-worktree)：多个检出目录共享对象和分支；锁、已占用分支及未提交文件影响工作树操作。

采用的交互原则是：工作目录靠近输入区，资源管理集中在设置，危险操作在具体对象上确认。页面沿用 Verse Claw 的中性色、菜单动效、字体、设置行和分隔线。

## 项目原有能力与本次实现

原有 `git-api` 已实现分支、工作树列表、创建和移除；会话输入区的 Git 面板可切换工作树。WorkspaceProfile 已持久化每个目录的会话、草稿、面板和 Agent 绑定，终端与浏览器也已有各自资源所有者。

本次补齐欢迎界面的工作目录选择、普通目录建立 Git 仓库，以及 `/storage` 和设置中的统一存储页。新工作树首次注册为独立 WorkspaceProfile 时生成新的会话键；后续切回该目录恢复已有绑定与草稿。项目名称使用分支名，侧栏可区分不同工作目录。

```text
Git 仓库（共享历史）
 ├─ 本地检出 → WorkspaceProfile → 会话 / 草稿 / 文件 / 终端
 └─ 工作树   → WorkspaceProfile → 会话 / 草稿 / 文件 / 终端

/storage ─┐
设置入口 ─┴─ 存储页 → typed host API → 现有 Git / 终端 / 浏览器 / 服务所有者
```

## 用户操作

1. 欢迎界面显示项目、执行目录和分支。普通目录可点击“建立 Git 仓库”。此操作不自动提交文件。
2. 点击“本地”或“工作树”，选择现有检出；“新建工作树”填写新分支与起始分支，创建后进入独立会话。创建使用已提交的版本，需要纳入的本地改动应先提交。
3. 已有会话继续使用输入框上方的 Git 面板切换分支、创建或选择工作树。
4. 输入 `/storage` 或打开“设置 → 存储空间”，查看应用内存、会话文件、会话进程与工作树文件占用。
5. 释放操作先确认，再停止所选会话的终端、浏览器和托管服务。消息记录与项目文件继续保留。归档会话的恢复和永久删除复用原有归档页。
6. 空闲、未关联工作区的干净工作树可以移除，分支继续保留。主检出、当前工作区、锁定、已关联工作区、运行中资源、存在本地文件/修改或不可读的目录会显示具体保护原因。

## 统计与操作契约

- 应用内存来自 Electron 进程指标。会话进程内存通过现有进程树采样器读取已归属的终端和托管服务 PID；浏览器未提供内存指标时显示未知。应用和会话指标不相加。
- 会话磁盘统计覆盖 `sessions.json` 解析出的本地对话文件，以及同目录的历史重置、轨迹和归档兄弟文件；不同工作区引用同一会话时，汇总按会话键去重。
- 工作目录统计包含普通文件与生成文件，跳过 `.git` 共享对象和符号链接/目录链接。扫描受条目数和时间限制；部分结果标记 `≥`，读取失败不会被当作完整零占用。
- 释放按 `workspaceId + sessionKey` 查找资源。观察到但未由应用管理的端口不被停止。
- 移除前重新读取 Git 与工作区所有者，拒绝主目录、当前目录、注册关联、锁和修改；通过现有权限系统确认后执行 `git worktree remove`，不使用 `--force`，不删除分支。
- Git 写入沿用工作区权限，readOnly/plan 下初始化和创建会被阻止；权限默认值继续由现有策略管理。
- 中文、英语、日语、俄语使用同一布局，文字来自现有 i18n 资源。

验收产物见 [报告与截图](../../harness/specs/fixtures/session-worktree-storage/20261107/README.md)。本次 145 项相关测试通过；真实 Electron 流程同时验证了终端资源释放和工作树移除后的分支保留。全量 Node 类型检查存在 `sessions-api.ts:1929` 的会话作用域签名冲突；完整工作区 Harness 因并行改动超出本任务文件范围失败，本功能明确文件范围的规则检查通过。

工作树管理从项目下拉菜单按需展开。空会话使用输入框下方的项目名称，已有会话使用顶部项目名称；两处接入同一个选择器，创建、切换和草稿保存仍由原工作区 owner 完成。
