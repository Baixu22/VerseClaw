### A5 CJK：修掉一处既有死代码（本轮第二个 A5 判例）

`GOAL_ANCHOR_PATTERN` 原形为单一正则，把 `目标|决策|约束` 与 ASCII 词一同放在共享的尾部 `\b` 前。**`\b` 定义在 `[A-Za-z0-9_]` 上，CJK 字符不是 word 字符，故 CJK 之后永远没有词边界** —— 这三个中文锚点**从写下之日起就是死的**。实测：

```
"目标：完成迁移"     -> false      "决策：保留旧 kid" -> false
"## 目标"           -> false      "GOAL: ship it"   -> true
/目标\b/.test("目标：x") -> false   /GOAL\b/.test("GOAL: x") -> true
```

已按脚本拆分为 `GOAL_ANCHOR_PATTERN_ASCII`（保留 `\b`）与 `GOAL_ANCHOR_PATTERN_CJK`（无 `\b`，加 `u` 标志）。这与 §R1.3 P5 的 `tokenizeWords` 判例**同类**：CJK 敌意匹配因测试语料全英文而长期存活。

## AC-5：v1 critical 触发器选型结论

**结论：T-C3 的 v1 critical 触发器不得单用 `goal_token_decay`；应以「分级 `goalAlignment`（有 objective 时）+ `goal_token_decay`（无 objective 时兜底）」为主信号，并把 `entity_loss_risk` 与 `actionability_loss` 作为独立的并联触发器。**

**为什么不能单用 `goal_token_decay`**，四条实测理由：

1. **它是二值的，没有梯度。** 触发器需要「何时告警、何时仅记录」的阈值，而 `goal_token_decay` 只有 fired / not-fired。分级信号在 `goalAlignment`（4-gram 覆盖率 0-100）上，二值旗只是它的一个阈值切片。
2. **无 objective 时它测不到真实目标。** 三条检测路径中只有第一条（objective 覆盖率）真的在测「这个会话的目标」；另两条（显式锚点 / 章节实质内容）是**启发式代理**。压缩钩子当前不传 objective，故生产路径实际走的是代理路径。
3. **代理路径会漏报。** 「章节有实质内容」只能证明*有信息*存活，不能证明*目标*存活：一份充满无关细节、但目标已丢的摘要仍会通过。这是 fallback 的固有上限，不是实现瑕疵 —— 也正是 T-C3 需要 objective 的原因。
4. **它曾经完全不可触发。** 修复前它在结构完整摘要上恒不触发；掏空摘要唯一触发的是 `entity_loss_risk` + `actionability_loss`。**那两个信号在最该告警的场景里是唯一可用的**，把它们排除在触发器之外会丢掉唯一的历史有效检出。

**给 T-C3 的三条落地建议**：

- **把 objective 传进压缩钩子**（`CompactionSafeguardRuntimeValue` 加字段），使主信号从代理切到直测。这同时解掉 AC-4 的 turnId 缺口 —— 两者是同一处管道缺失。
- **触发器取并集，不取单信号**：`goalAlignment < 70`（既有告警阈值）OR `goal_token_decay` OR `entity_loss_risk`。三者失败模式不同，冗余是有价值的。
- **先修 backlog-P1 第 1 条**（桥接丢弃 `entity_loss_risk` / `actionability_loss`），否则 T-C3 从 scorecard 上读不到这两个信号。

阈值取值：`GOAL_RETENTION_MIN_COVERAGE = 0.2`，刻意低于健康分的 `goalAlignment` 告警阈值 70，使**二值旗不会比分级维度更晚告警**（分级先 warn，二值后 fire）。
