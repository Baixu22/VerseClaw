## 结论

**迁出。**

本 task 只做裁决，不改代码、不改配额、不改阈值、不做 θ 定标。实现动作移入第二轮。

## 依据

1. **生产调用面没有真实 embedding provider。**
   - `memory-context-provider.ts` 的生产构造点没有传入 `embeddingProvider` 或 `embeddingEnabled`。
   - `useEmbedding` 三个合取项中，`options.embeddingEnabled` 在生产调用面恒为 falsy。
   - `check-production-reachable.mjs hybridSearchFactsWithEmbedding` 显示符号在 import 图上可达，但这不等于运行时通电；实际生产路径仍走 `findRuntimeMemoryFacts`。

2. **其他入口也是默认关。**
   - `enablePreReplyRetrieval` 默认 `false`。
   - `memory_query` 属于 COMPASS 实验面，不是本轮生产主路径。

3. **外部证据不支持为它补一条自研检索栈。**
   - Letta 的 LoCoMo 评测显示 Filesystem 74.0%，并不输给专用记忆工具。
   - CoALA 把 retrieval 归为 decision procedure，但没有要求自研 BM25/vector/RRF。
   - Context Rot 说明低相似度退化更快，但当前链没有证明自己能解决这个问题。

4. **维护成本不对称。**
   - `memory-hybrid-retrieval.ts` 约 1127 行，核心价值集中在 BM25、向量、RRF 融合与索引。
   - 生产真正需要的是少量文本工具：`tokenizeWords`、`extractEntities`、`keywordOverlap`、`characterNgrams`。
   - 为一条未通电的检索栈继续维护完整实现，收益低于成本。
