## 一处共用工作树的处置（`package.json`）

`package.json` 带**第三方既有未提交改动**（把 `test:dcs` 第 2/3 段 invocation 的路径去掉 `src/` 前缀）。而 AC-2 要求我改同一文件同一行 —— `git commit -- package.json` 会把对方的改动一并卷入（`TFD-lane1-index-bleed` / `TFD-lane2-rollback-drill-index-mutation` 同形）。

处置（**worktree-only，全程不写 index**，沿用 §R5 回滚演练已验证的手法）：

1. `git diff -- package.json > pkg-thirdparty.patch`（先存对方的 hunk）
2. `git apply -R pkg-thirdparty.patch` → 工作树回到 HEAD
3. 做我的改动 → `git commit -- package.json`，实测提交 diff 为 **1 insertion / 1 deletion，且不含对方任何一行**
4. 还原对方 hunk

**第 4 步实测失败并已修正**：`git apply` 报 `patch does not apply` —— 因为对方的 hunk 与我的改动**落在同一行**，我提交后上下文已变。若就此停手，对方的未提交工作会**从工作树上消失**。改为按对方 patch 的 `+` 行取其完整意图值、在其上重放我的两处追加，得到「对方规范化 + 我的注册」的合并态。

复核：`test:dcs` 仍是合法 JSON；我的两个文件在内；对方的两处规范化在内（`config/runtime-context-block-compass.test.ts` 在、`src/config/...` 不在）；当前未提交 diff **恰为对方那 1 行**。合并态下 `test:dcs` **exit 0**。

> 教训值得单记：**「先撤对方改动 → 提交 → 再还原」这套手法，在两人改同一行时第 4 步会失败。** 撤销前必须确认对方 hunk 与自己的改动不共行；共行时须按语义重放而非按 patch 还原。建议 §R4.3 收口条款采纳。
