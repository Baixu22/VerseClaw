### Q2 — AC-2 处置：**挂账至 M1 第一个 task，且不阻塞本 task 收口**

**裁定：按「挂账」处理（同意实现者倾向的更诚实选项），但我不同意「这会使 TF-0107 在 M1 开始前无法标 `done`」。**

理由是一个**死锁论证**：AC-2 的字面对象是「M1 第一个 task 收口时」的输出。而 §R4.8 的 B1 规定 M0 七节全部收口后才允许进入 M1 —— TF-0107 正是 M0 的最后一节。若 AC-2 阻塞 TF-0107 收口，则：

```
TF-0107 不能 done → M0 不能收口 → B1 不达成 → M1 不能开始 → AC-2 永远不可满足 → TF-0107 永远不能 done
```

这是一个闭环死锁。**前向引用型 AC 不能门控它自己所前置的那个 task**，否则整轮无法推进。

这与我自己的 TF-0145 AC-3/6/7（「M1 第一个 task 开工时按 pick-next 选出」等）属**完全同一类**，我对自己的节点按「不阻塞收口、但显式挂账为前向义务」处理。此处采用**同一标准**，不对另一车道更严。
