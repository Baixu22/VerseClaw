## 三点裁定

### Q1 — `maturity:validate` 的 `&&` 链盲区：维持 backlog，但盲区必须留在 L2 判据里

**裁定：维持 backlog，不升级为本轮必查。**

理由：第 5/6 个脚本（`residual-audit` / `traceability`）从未执行，其状态是**未知量**而非已知绿 —— 实现者主动指出这点是加分项，很多人会写成「maturity 只有 25 项问题」。但要消除盲区就得让这两个脚本跑通，而它们属 TF-0028/TF-0029 的未完成交付物，**根因在本轮范围-1 之外**（§R5 范围-2）。本轮强行纳入会把 M0 的收口挂在别的 global_task 上。

按三分类记为 **`backlog-debt`**，归属 TF-0028 / TF-0029。**§5.2 已要求 L2 判据单独跑这两个脚本**，该要求必须保留 —— 它是盲区不被遗忘的唯一机制。

### Q2 — 白名单内嵌 JSON 而非旁挂 `.json`：内嵌正确

**裁定：内嵌 JSON 是正确选择，维持。**

§R4.1 明确「本轮全部产出物只允许落在此树下，路径以外的产出物视为未交付」，且七个约定路径中**没有** `.json` 数据文件的位置。新增一个旁挂 `.json` 会立即制造第二个「工具类例外」（目前唯一例外是 §D1.2 的判据脚本，且它由两个节点的 AC 双重指定）。

内嵌 + 定界注释 + **实测可切片可解析**（取证 5）已完全满足 AC-2「可被脚本消费」。AC-2 要求的是可消费性，不是文件形态。

### Q3 — `exempt-noise` / `backlog-debt` 边界的相关性局限：接受

**裁定：接受该局限，且认定它不构成判据缺口。**

实现者想用 stash 分离「未提交改动引起」与「committed 既有债务」，但 §R4.9 规定既有未提交改动不属任何车道、不得 stash（两车道共用工作树，stash 是跨车道写）。**该禁令优先，实现者遵守是正确的。**

关键是实现者自己给出的论证成立：`exempt-noise` 与 `backlog-debt` **对 L1/L2 的效力完全相同**（均入白名单、均不阻塞），差别只在 backlog 归属登记。故该局限影响的是「债务归给谁」的准确度，不影响任何门的行为。**判据无缺口。**

补充佐证：取证 8/9 的漂移项恰好是一个 `exempt-noise/env-platform` 项，其翻转正符合该类的预期行为，说明分类轴本身是有判别力的。
