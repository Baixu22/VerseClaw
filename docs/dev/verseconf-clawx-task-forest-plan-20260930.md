## 3. 下一步只执行 TF-0244

### 输入

[ClawX 接入探索方案](verseconf-clawx-integration-exploration-20260930.md)，重点看受管提交、身份／版本、分阶段工作和验收设计。

### 最小交付

1. 三条记录的严格 JSON 研究表夹具。
2. 一次两字段联合修订请求，包含稳定 ID、baseRevision 和 expect。
3. 独立预期值与非目标字节判据，不能让被测编辑器自证修改范围。
4. 真实 run 提交路径设计：插件上下文、策略、写入 owner、journal、收据与源运行时隔离。
5. 五类失败路径的输入、预期副作用和取证方法：
   - 只读／拒绝；
   - 读取后基线漂移；
   - 提交前取消；
   - 源已提交但导出失败；
   - 提交后中断并重启对账。
6. 有限维护范围、资源上限、工作量建议与不可事后放宽的停止条件。

建议未来交付位置为 `docs/dev/verseconf-clawx-contract-v1.md` 与 `artifacts/verseconf-contract-v1/`，当前尚未创建，不是已有验收证据。

## 4. 有限实施决定怎么处理

TF-0245 是真实的范围／冻结／预算决定，不是让发布者补设计细节，也不是要求真人测试。

- Agent 先给出完整建议与依据。
- 涉及冻结资产例外或产品范围调整时，记录明确授权，只覆盖选中的 ClawX 消费者与 Node 内存绑定。
- 本次“开始 TF 规划”的请求不被登记为全面解冻或产品改造授权。
- 若决定停止，必须在记录停止的**同一提案**中废止后续未执行实现节点；不能只把 decision 标 done，导致调度器把后续 proposed 节点误视为可启动。
- 普通实现、测试、文档、证据与有据收口继续由 agent 自主处理，不要求真人数据或人工 verdict。
