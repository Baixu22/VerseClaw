# O01：审批分类率诊断

仅实现诊断日志，不实现审批自动化或新看板。计数是write/edit/apply_patch破坏性分类中requiresApproval的比例，不是UI对话框/真人决定次数。

## 启用与范围

现有配置diagnostics.enabled必须显式为true，且进程诊断开关开启。省略或false不收集新窗口、不写新告警；累计计数和工具行为不变。范围为单运行时进程，不是per-run或Main进程副本。沿用现有日志级别、文件和log.record通道。

## 预登记窗口

- 仅保存最后100个已监测分类及时间；每20个新分类评估一次，至少20样本。
- 连续两窗比例≥0.5告警；告警后连续两窗≤0.3清除。中间区间重置连续计数，不自动清除已有告警。
- TTL为300000ms。零/不足/过期、时钟无效/回退为unavailable，rate=null，不能当正常。
- 重复读取不改变连续窗；没有后台定时器。过期在下一次观察/读取处理，日志的expiresAt不是实时轮询承诺。
- 参数是显式诊断试用preset，不是安全阈值，不新增配置键或修改生产冻结默认。

## 消费者与故障

真实路径：工具工厂的显式选择→原分类包装器→原累计计数与有界窗口→diagnosticLogger→现有日志/log.record。记录样本、窗口、原因、建议，不记录工具参数。消费者异常不改变工具结果，下一次观察可重试。关闭后清掉诊断窗口，不回填/重放旧分类。

验收以o01-acceptance.json及O01-SHA256SUMS为准；未生成前不声称已通过。B00历史摘要保持原样。UI、真实模型、六pilot和发布不属于本包。

逐个TTL淘汰但仍有足够新鲜样本时，继续每20个新有效分类评估，不能不断重置步长而使告警/清除饿死。实际不足样本会重置确认序列，不能用未测窗口预先确认。未选择监测的分类结束当前窗口，避免跨未覆盖时段拼接统计。

TTL边界的精确补样允许连续确认；任何正持续时间的不足样本区间，即使到达样本把数量恢复到20，也使旧确认失效。按到达前的TTL覆盖推断，不新增后台定时器。
