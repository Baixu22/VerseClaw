## 2. 依赖与平台核对

仓库 memory-lancedb package 声明 @lancedb/lancedb 0.30.0。npm同版本元数据为Apache-2.0、Node>=18；列出的native packages包含：

- macOS arm64；
- Linux x64/arm64 的 GNU 与 musl；
- Windows x64/arm64 MSVC。

没有列出darwin-x64。本仓实际release matrix包含macOS x64/arm64、Windows x64和Linux x64/arm64。因此长期方案不能假设“已有LanceDB依赖”就覆盖全部目标；必须提供portable路径和真实打包probe。当前工作区未安装可直接加载的该SDK，本次没有以依赖声明冒充native运行验证。

这里的LanceDB是向量投影实现，不是memory-lancedb插件整体复用。后者还带memory store/forget、自动recall/capture，直接启用会跨越Knowledge的权限和写入边界。

## 3. 从源码进一步确认的复用点

- memory-core/runtime-api.ts 公开 createEmbeddingProvider，内部已经适配generic registry、query/document inputType和dimensions。
- memory-host-sdk/host/embedding-defaults.ts 选择EmbeddingGemma QAT Q8_0 GGUF。
- FactStore已有FTS、RRF和局部图关系，可复用算法和已有数据，不复制成新图数据库。
- KnowledgeStore已有versioned exposure/adoption/outcome事务，RAG不另造采用计数器。
- SourceSet已有准入、冲突与证据状态，但普通Chat的版本/政策传递、DCS保序和原子装配仍需实施。
- 当前main已提交代码与首轮工作区比较中，30个源文件文本一致，3个Chat文件重新核对；首轮93项测试保留原基线解释。

## 4. 不纳入长期主线的技术

- 全量GraphRAG/LightRAG实体抽取与社区摘要：维护/删除传播成本与项目源频繁更新不匹配；当前需求已有code/wiki关系入口。
- 语义切块默认开、每次query整库embedding、LLM列表式rerank：没有本项目消融证据，且会扩大预算与恢复复杂度。
- 把Memory、Task Ledger、SEKB复制成一个canonical store：破坏既有owner与保留策略。
- 从attach/dismiss实时学习在线权重：缺少因果与独立评测，也会模糊用户scope和默认策略。
- 强制外部托管向量数据库、强制Docker/独立Python serving作为桌面基础依赖：local portable语义路径必须可用。
- 把模型参考名或SDK支持列表当性能/安装验收：所有声明以对应平台和候选实际probe为准。

## 5. 可改变实现参数的证据

架构目标已固定；模型、维度、chunk策略和ANN参数通过版本化policy更新。先冻结数据与预算，比较recall/nDCG、引用/语义支持、端到端任务结果和成本，再发布新profile。失败保留并回滚，不能把“已探索”写成“已经改善”。
