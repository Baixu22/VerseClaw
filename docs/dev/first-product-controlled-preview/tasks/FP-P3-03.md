## Goal（用户可见结果）
在一台干净的 Windows x64 机器上：能装、能首启、能升级/恢复/回滚/卸载；本地 Git 和 GitHub Forge 在 `git/gh` 缺失、未认证、已认证三种状态下均能安全解释和降级，凭据与旧审批不泄漏、不误复用。

## Why this exists
开发机绿灯不代表用户机可装。首产品是要发给别人用的，安装/升级/回滚是唯一没有替代证据的一环。当前完全缺失。

## Non-goals
- 不做多语言 OS 矩阵（选 zh-CN + en-US 两档即可）
- 不做 ARM64
- 不做企业批量部署（MSI/GPO）

## 演练矩阵
| # | 场景 | 期望 |
|---|------|------|
| 1 | clean VM 安装 | 成功，无需手工前置依赖 |
| 2 | 首次启动 | Setup 流可完成（含 Provider/Model/Workspace） |
| 3 | N-1 → 当前版本升级 | 成功；Provider / 会话 / workspace 数据保留 |
| 4 | 升级失败恢复 | 有可行恢复路径（回退或重装保数据） |
| 5 | DCS flag rollback | 关掉后回基线，无残留 ON |
| 6 | 应用版本回滚（当前 → N-1） | 成功；数据兼容或有明确降级说明 |
| 7 | 卸载 | 残留数据策略明确并与实际一致（留/删/提示） |
| 8 | 安装包完整性 | hash 与 feed / release-info 一致 |
| 9 | SmartScreen 行为 | 未签名产物的实际表现被记录（不试图绕过） |
| 10 | `git` 可用、repo workspace | 本地 Git 工作台/MCP 正常，权限与路径边界不变 |
| 11 | `gh` 缺失或未认证 | DCS coding 与本地 Git 可用；Forge 明确 unavailable/unauthenticated，不崩溃、不诱导 merge |
| 12 | `gh` 已认证 + sandbox repo | PR read/review/readiness/approval-bound merge 与 P2 裁决范围一致 |
| 13 | 升级/回滚后的 Forge 状态 | 凭据仍由既定安全来源管理；旧 approval/headSha 不可复用；support bundle 无 secret |

## Acceptance criteria
- [ ] 13 个场景全部执行，逐条记录结果（含截图或文本证据）
- [ ] 场景 3 的数据保留清单明确列出（Provider 配置、会话历史、workspace 绑定、flag 状态）
- [ ] 场景 5 验证 flag 不因升级自动翻开
- [ ] 场景 7 的残留策略写进文档并与实测一致
- [ ] 证据落 `artifacts/first-product-preview/FP-P3-03/`
- [ ] VM 环境信息记录（Windows 版本、是否联网、是否加域）
- [ ] 未签名产物的 SmartScreen 表现记录，且明确「仅内部 Alpha」
- [ ] `gh` 缺失/未认证时 DCS coding 与本地 Git baseline parity 通过，Forge 显示可操作的降级原因
- [ ] 已认证 sandbox 场景只执行 P2 charter/裁决允许的 action，生产 repository 远端副作用为 0
- [ ] 升级/回滚后旧 action-bound approval、旧 head SHA 和旧 readiness digest 均不能触发 merge
- [ ] VM 日志与 support bundle 扫描无 Token/Authorization/私有 URL/源码正文
