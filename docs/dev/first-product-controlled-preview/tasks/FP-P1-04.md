## Goal（用户可见结果）
用户在产品聊天里提一个真实编码需求，agent 能读上下文、改文件、给出 diff、跑语法/测试校验，用户不满意可一键 undo 回到修改前状态。

## Why this exists
这是首产品**唯一**承诺的垂直链路。当前各段能力分别存在（BlockStore 工具已注册、write journal/undo 已有、diff/test 分散），但没有一条被证明端到端可用于真人任务（L3 = 0）。

## Non-goals
- 不做 WAL、不做默认 worktree、不做默认 patch-flow
- 不做多文件大规模重构编排
- 不做 SEKB 写回 / RM 注入

## 链路分段与各段验收
| 段 | 必须做到 | 失败可解释 |
|----|----------|------------|
| read | 命中 workspace 内相关文件/块，命中数可观测 | 无命中时明说「未命中」，不静默 |
| write | 仅限 workspace；写前记 journal | 越界/只读时拒绝并说明 |
| diff | 展示实际落盘前后差异 | diff 生成失败时不静默应用 |
| verify | 语法检查 + 可用则跑相关测试 | 无 test runner 时明说跳过原因 |
| undo | 100% 还原本次会话写入 | 部分还原视为失败 |

## Decision

1. **verify 段只探测不执行**。测试执行交给既有 exec/bash 工具，以继承其审批 / 沙箱 / 超时策略。
   否决「在 write-side-effects 里直接跑测试」：会绕开审批面并在写路径上引入不可控时长。
2. **diff 证据走 `content` 而非 `details`**。实测 `gateway/chat-display-projection.ts:472-473`
   对 chat history `delete entry.details`，故 `details` 里的 diff 用户永远看不到。
   先在 emit 层拼接的尝试无效（非 Electron 渲染源），已整段回退。
3. **npm 占位脚本不算 runner**。`"no test specified"` 若当成真 runner，会让每个未测项目
   都报硬失败；改为独立 skipReason `placeholder-test-script`。
4. **失败路径改选**。任务书原列「无权限 / 文件被占用 / 磁盘满 / 写中断」，
   后两者在 CI 内只能靠伪造 IO 层制造，属于「测 mock 而非测产品」。
   改用同类别但真实可复现的三类失败，并保留越界拒绝由 FP-P1-02 覆盖。原条目未删，见上。
