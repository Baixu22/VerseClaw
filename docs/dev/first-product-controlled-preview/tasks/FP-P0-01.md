## Goal（用户可见结果）
干净安装、未做任何 opt-in 的用户，其 gateway child 里 VToken assembly 实际为 **OFF**；`docs/dev/default-config-matrix.md` 声明的 `false (opt-in)` 与真实进程一致。

## Why this exists
runtime resolver、文档、测试三处都声明默认 OFF，但 Electron 启动层无条件把 env 注成 `1`：
- `electron/gateway/process-launcher.ts:122-123`（缺值即写 `'1'`）
- `electron/gateway/config-sync.ts:1029-1030`（`|| '1'`）

结果是「声明 OFF、实际 ON」，任何基于默认值的 baseline parity 与 canary 结论都不可信。这是首产品两个最硬运行时阻塞之一。

## Non-goals
- 不做 VToken 能力增强或 opt-in 毕业（→ `FP-P4-03`）
- 不改 runtime resolver 的语义（resolver 已正确）
- 不顺手翻其他 flag

- `electron/services/vtoken-bridge.ts:60,68`（kill 语义参考）
- `openclaw_runtime/src/context-engine/vtoken-rpc-client.ts:416,426`（resolver 真相）

## Decision required（实现前先定）
三选一并写入本文档：
- **A**（推荐）启动层不再注入默认值，交给 runtime resolver 判定；仅当用户显式 opt-in 时注入 `1`。
- **B** 启动层注入 `0`，把 OFF 变成显式声明。
- **C** 改文档/测试承认默认 ON —— **不采用**，与首发范围「VToken 排除」冲突。

## Decision

**结论：选 A —— 启动层不再注入默认值，交给 runtime resolver 判定。**

决定日期 2026-07-26；决策人 Claude（实现人）；B 被否，C 被 Hard locks 排除。

### 为什么是 A

1. **A 是唯一能同时满足两条 Acceptance 的方案。** matrix 声明 opt-in 有两条互不依赖的通道：config `runtime.vtoken.assembly.enabled=true` 与 env `=1`。resolver 里 config 通道能生效的**前提**是 env 未被判为 kill。
2. **B 会把 config 通道打死。** 启动层注 `'0'` → child 内 `isVtokenAssemblyEnvEnabled()` 返回 false → `resolveVtokenAssemblyConfig` 在读 config 之前就 early-return `enabled:false`。用户即便写了 `runtime.vtoken.assembly.enabled=true` 也永不生效，等于把 opt-in 通道从两条砍到一条，且与 `default-config-matrix.md:14` 冲突 —— 那就得改文档，绕回被 Hard locks 排除的 C。同时 B 会连带把 `vtoken-bridge.ts:68` 的 assembly-kill 分支永久点亮，bridge 的 `setEnabled(true)` 也失效。
3. **B 抹掉运维可观测性。** 注 `'0'` 后「产品默认」与「operator 主动 kill」在 child env 里长得一样，事故复盘无法区分。
4. **A 不需要新写 pass-through 代码。** `config-sync.ts:1016-1017` 的 `...stripSystemdSupervisorEnv(baseEnvPatched)` 已经把 `process.env` 整体铺进 forkEnv，用户 shell 里的 `=1` / `=0` 天然继承。删掉强注后：unset→child 不含该键→resolver 判 OFF；`=1`→canary on；`=0`→kill，且优先于任何启用来源（resolver 先判 kill）。
5. **A 让 `default-config-matrix.md` 不改也能通过**，正是完成态要求。

### A 的实现边界

- 两处都删：`config-sync.ts` 的 `|| '1'` 与 `process-launcher.ts` 的 `if (!…) = '1'`。只删一处会被另一处兜回 ON。
- **不新增** Settings 开关/store key。今天的显式 opt-in 通道 = openclaw config 或 env；UI opt-in 面属 `FP-P4-03`，本任务 Non-goals 已排除。
- 不动 resolver 语义、不动 `vtoken-bridge.ts`、不动 `VERSE_VTOKEN_PACKAGE_ROOT`（package root 与启用无关，保持无条件注入）。
- `docs/dev/dcs-visible-production/tasks/TASK-P1-04.md:36,70` 记录了旧的「default 1」描述，属前序 program 的历史记载；本任务不改前序文档，若需纠正则登记为残留。
