## Goal（用户可见结果）
在慢机器 / 冷启动上翻开关，不会因为 gateway 起得慢就被误报成「未确认」。

## Why this exists
`FP-P0-04` 的 ack 轮询用固定值：`DCS_FLAG_ACK_TIMEOUT_MS = 20_000`、
`DCS_FLAG_ACK_POLL_INTERVAL_MS = 500`（`electron/services/dcs-flag-ack.ts`）。
20s 是拍的，不是测出来的。实测 gateway 冷启动在本机约需数十秒量级（E2E 里
`ensureGatewayRunning` 给了 180s 上限），所以真实产品路径下 `ack-timeout →
pending-restart` 可能是常态而非异常 —— 这会让状态机的诚实性变成噪音。

## Non-goals
- 不改状态机语义（五态与七字段不动）
- 不把超时后的 `pending-restart` 改成 `applied`（那是假 done）

## Context / code anchors
- `electron/services/dcs-flag-ack.ts`（`DCS_FLAG_ACK_TIMEOUT_MS` / `POLL_INTERVAL_MS`）
- `electron/services/dcs-prod-flags-api.ts`（`collectRuntimeFlagAck` 调用点）
- `tests/unit/dcs-flag-ack.test.ts`（超时双分支用例）

## 实现要点
1. 先**测量**：在冷/热启动、有/无 source-runtime 隔离下各测数次 restart→ack 时延，数据入档。
2. 依数据定超时（含余量），而不是先定值再解释。
3. 参数化：允许 openclaw config 或 AppSettings 覆盖；默认值来自测量。
4. 轮询改指数退避（避免慢启动时 40 次无效 RPC）。
5. 超时后 UI 需可**重查**而不必重翻开关（复用现有 `pending-restart` + 刷新路径）。

## Acceptance criteria
- [x] restart→ack 时延实测数据入档（≥5 次，含冷启动）→ 5 次真 Electron 内真 child 冷启动（5 个不同 pid，各为新进程冷启动），ackWaitMs 11633-12729ms；数据与口径见 [evidence.md](../../../../artifacts/first-product-preview/FP-P1-09/evidence.md)。注：child 在 Electron utilityProcess 之外不监听端口，独立脚本测不出真值，故以生产同路径 E2E 实测为准（脚本保留于 scripts/measure-flag-ack-latency.mjs）
- [x] 默认超时由数据推导，写明余量算法 → 余量规则「默认 ≈ 4× 实测最大值」：60000ms ≈ 4.7× max(12729)；旧 20s 仅 1.57× 属拍值，已被数据否定
- [x] 超时/间隔可配置，配置缺失时回落到默认 → AppSettings `dcsFlagAckTimeoutMs`/`dcsFlagAckPollInitialMs`（0=默认；clamp 1s-600s / 50ms-10s），`resolveDcsFlagAckTuning` 单测覆盖缺失/0/NaN/负数回落
- [x] 指数退避落地，慢启动下 RPC 次数显著下降（贴前后对比）→ 250ms 起倍增至 4s 顶；60s 静默窗口 120 → 19 次（-84%），`[fp-p1-09-rpc-count]` 单测实测
- [x] 超时后可重查，无需重新翻开关 → 新增 `dcsProdFlags.requeryAck`（contract+facade+service+UI 按钮，仅 ack-timeout 态出现）；E2E 实证：requery applied 130ms、childPid 与上轮相同、gateway 状态未变（未重启未改写）
- [x] 既有超时双分支单测仍绿 → 18 条 FP-P0-04 用例零修改全绿（23 passed 总）
