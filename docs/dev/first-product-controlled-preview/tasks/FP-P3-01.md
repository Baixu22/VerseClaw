## Goal（用户可见结果）
存在一个干净、可复现的发布快照：固定 SHA、工作树无游离改动、manifest/evidence/ref 全新鲜、校验脚本全绿。

## Why this exists
本轮审计实测三处红灯：
- `git diff --check` 失败（trailing whitespace）
- `pnpm run release:baseline:validate` 失败（无 fresh manifest/evidence/ref）
- 工作树不是发布快照（约 167 staged / 67 unstaged / 25 untracked）
- `release/win-unpacked/resources/app.asar` 早于最新 `dist`，不能作为本轮 RC

在这些红灯下打出的包无法追溯，也无法在故障时定位到确切代码。

## Non-goals
- 不做代码签名（公开发布另立任务）
- 不做 CI 流水线重构
- 不顺手合并无关改动

## Acceptance criteria
- [ ] `git diff --check` 干净
- [ ] 工作树分类完成：该提交的提交、该忽略的入 `.gitignore`、该删的删；发布 SHA 上无未跟踪产物
- [ ] `pnpm run release:baseline:validate` 通过（贴输出）
- [ ] fresh manifest / evidence / ref 生成并与 SHA 绑定
- [ ] `FP-P2-07`–`10` 的 contract/provider/Main/host-api/MCP/UI/test 源码全部被 Git 跟踪并进入 manifest
- [ ] MergeBeacon 上游 commit、快照 hash、Apache-2.0 attribution/修改声明进入 release evidence
- [ ] `dist` 与 `release/win-unpacked/resources/app.asar` 时间与内容一致（重建，不复用旧 asar）
- [ ] 发布包不捆绑未声明的 `git`/`gh`；系统 `gh` 缺失时的安全降级策略与实际一致
- [ ] 安装包、manifest、support bundle 和日志扫描确认不含 Token/Authorization/私有 URL/源码正文
- [ ] 安装包 hash 与 feed / release-info 声明一致
- [ ] `assert-release-version` + `validate-windows-release-policy` 通过
- [ ] 记录发布 SHA，并与 `FP-P2-01` charter 的 `versionSha` 关系说明清楚（相同或已重新计数）

## Implementation slices
1. 工作树分类与 whitespace 修复
