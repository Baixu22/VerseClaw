## Goal（用户可见结果）
Canary 开始前，DCS coding 与 GitHub Remote Forge 的所有边界写死在一份文件里：谁负责、谁参与、跑哪个版本、允许操作哪些 workspace/repository、花多少钱、数据留多久、什么条件停。

## Why this exists
前序 `TASK-OPS-01` 的 6 个 run 全部 `notHumanProductChat=true`，且缺少固定 owner/cohort/审批人。新增 Remote Forge 后还存在远端评论、metadata 和 merge 副作用；没有统一治理包，10 次真人任务与 GitHub canary 的结论都无法被采信，也无法判断何时该停。

## Non-goals
- 不执行 canary（DCS + GitHub Forge 真人消费统一归 `FP-P2-02`）
- 不做 default-on 决策（→ `FP-P2-03` 只出 continue/shrink/stop）
- 不建外部遥测
- 不扩到 GitLab/Gitee/PR DAG（→ `FP-P4-08`）

## Stop conditions（最小集，任一命中即停）
- 未授权写入 ≥ 1
- secret 泄漏 ≥ 1
- undo 失败 ≥ 1
- kill/rollback 失败 ≥ 1
- baseline parity 回归
- 未授权远端评论、metadata 或 merge ≥ 1
- stale head/readiness/approval 未阻断 ≥ 1
- `unknown` / `incomplete` readiness 被当成 ready ≥ 1
- Token、Authorization、私有 URL 或源码正文进入日志/support bundle ≥ 1
- 成本超 `costCeiling`
