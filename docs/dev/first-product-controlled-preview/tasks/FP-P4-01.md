## Goal（用户可见结果）
用户在产品内完成完整的知识沉淀闭环：suggest → review → confirm/reject → retrieve，且确认前绝不写回。

## Why this exists
后端 golden path 已有 human confirm 且确认前不写回（前序 `TASK-P1-05` done），但 renderer 只有 facade，没有真正的 suggest/review 页面。因此这个能力对用户不可见 —— 属于典型 shelfware，只是尚未被首产品需要。

## Non-goals
- 不做自动写回（**永久硬锁**）
- 不进 Controlled Preview 首发范围
- 不做知识图谱可视化

## Implementation slices
1. **contract audit + Harness**：复用既有 `sekbSuggestPrinciples`、`sekbConfirmPrinciple`、`sekbRejectSuggestion`、`sekbRetrieveForTask` typed host-api；冻结确认前零写回与 default-off 边界。
2. **Runtime Lessons workspace**：在 Knowledge 页面展示 undistilled trajectories、active principles、index preview 与明确不可用/空状态。
3. **suggest + review**：显式请求 deterministic suggestions，展示 cluster、confidence、source trajectory lineage 与 proposed principle 字段；浏览和编辑不写回。
4. **confirm / reject**：confirm 需要可见 session lineage 并走 `ui-confirm`；reject 只调用现有 rejection action，二者均保持可解释状态。
5. **retrieve**：按 task intent/type/tags 检索已确认原则并展示 advisory injection，不自动注入会话。
6. **verification + evidence**：单测零写回/confirm/reject/retrieve，Electron E2E 完整闭环，四语 i18n、contract/harness/comms 与 fixture-grade evidence。
