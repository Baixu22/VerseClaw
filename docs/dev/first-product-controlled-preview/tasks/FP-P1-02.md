## Goal（用户可见结果）
用户在开始第一次编码任务前，明确选定**一个** workspace 并明确授予写权限范围；越界写入在运行时被拒绝并可解释。

## Why this exists
首发范围是「单 workspace、指定目录受控写入」。历史上存在两套断链 workspace 体系与「cwd 第二权威」问题（见 memory `dcs-p0-preflight-findings`）。没有 preflight 与权限权威，就无法承诺「未授权写入 = 0」。

## Non-goals
- 不做多 workspace 并行
- 不做 worktree 默认化（保持 `worktree=inprocess`）
- 不做细粒度 per-file ACL

## Preflight 检查项
| 检查 | 失败处理 |
|------|----------|
| 路径存在且是目录 | 阻断，提示重选 |
| 可读 | 阻断 |
| 可写 | 阻断或降级为只读模式（明确告知） |
| 是否 git 仓库 | 非阻断，但影响 undo 策略提示 |
| 是否命中敏感路径（系统目录、家目录根、含凭据文件） | 警告或阻断 |
| 磁盘剩余空间 | 警告 |

## Acceptance criteria
- [x] Setup 中必须选定 workspace 才能进 Complete（或显式进入只读模式）→ WORKSPACE 步 `canProceed = workspaceConfirmed !== null`；不可写目录强制只读档（`readOnlyOnly` 显式降级提示）；E2E 断言未确认时 Next disabled
- [x] 权限选择至少两档：只读 / 受控写入（限定 workspace 内）→ `WorkspaceStep.tsx` 双档显式选择（readOnly / acceptEdits），受控写入描述明确「越界与高危命令仍需审批」
- [x] 运行时越界写入被拒绝，错误里能读出「越界」与实际边界 → denial reason 现含边界路径（workspace-permissions.ts）；E2E 实测 approval.reason=“Write target is outside the workspace boundary (…\workspace)…”
- [x] cwd 不再构成第二权威：workspace 是唯一写入边界来源 → `syncActiveWorkspaceRootToRuntime` 把 active profile rootPath 钉进 `agents.defaults.workspace`（create/update/switch/delete 全路径同步），gateway agent 与 UI 判同一边界；`~/.openclaw/workspace` 回落仅在从未选过 workspace 时存在
- [x] 敏感路径命中有显式提示 → 六检查之一：盘根/家根/系统目录/凭据目录=阻断，目录内含凭据材料=警告（含命中文件名）；E2E 实测 C:\Windows 被阻断
- [x] 单测覆盖：越界写、符号链接逃逸、相对路径穿越（`../`）→ `tests/unit/workspace-preflight.test.ts` 14 用例（穿越 resolved-first、junction 逃逸、readOnly 拒写、边界命名断言）
- [x] E2E：选 workspace → 写入成功 → 越界写入被拒 → 1 passed 22.7s；inside 写入落盘验证、outside+traversal 拒绝且盘上无文件
