## Goal（用户可见结果）
冻结可追溯的 MergeBeacon 来源，并让 DCS Work panel、Git 工作台、Code Review、Agent artifact 和后续 Remote Forge 使用同一版本化 patch/error contract；`edit` 与全文件 `write` 都能产生可核对的富 diff，大 Diff、binary、rename、截断和远端错误都能稳定解释。

## Non-goals
- 不改变 `apply_patch` mutation/原子性语义（归 `TF-0015/UAS-04`）
- 不新增远端 PR 写操作
- 不照搬 MergeBeacon 的 Tauri/Vue/Rust 架构或固定限额

## Acceptance criteria
- [ ] 冻结上游 URL、commit、tag、本地快照 hash、许可证和取得日期
- [ ] 解释 README `0.8.0` 与 manifest `0.10.0` 漂移并产出文件级处置矩阵
- [x] 定义 `GitPatchArtifact/v1`：file/status/oldPath/newPath/contentKind/hunks/oldLine/newLine/message/completeness
- [x] 定义 `RemoteForgeError/v1`：code/retryable/requestId/httpStatus/safeMessage
- [ ] 统一 CRLF、裸 hunk、rename、binary、metadata-only、malformed、truncated 行为
- [ ] Git/Code Review/diff extension 的 size limit 有统一策略和明确降级原因
- [ ] malformed patch 不 panic；`truncated/unavailable` 不伪装成空或完整 Diff
- [ ] DCS `edit` 结果经 `GitPatchArtifact/v1` 投影为 `code-diff` 富组件，同时保留可复制的文本降级
- [ ] DCS 全文件 `write` 产生真实 old/new diff，不再只返回 `different/same/unknown` 预检
- [ ] 富组件、文本降级、Agent artifact 和 journal lineage 指向同一 mutation/request，不建立第二写入 authority
- [ ] Apache-2.0 attribution/修改声明处置清单入档
