## Goal（用户可见结果）
冻结可追溯的 MergeBeacon 来源，并让 DCS Work panel、Git 工作台、Code Review、Agent artifact 和后续 Remote Forge 使用同一版本化 patch/error contract；`edit` 与全文件 `write` 都能产生可核对的富 diff，大 Diff、binary、rename、截断和远端错误都能稳定解释。

## Non-goals
- 不改变 `apply_patch` mutation/原子性语义（归 `TF-0015/UAS-04`）
- 不新增远端 PR 写操作
- 不照搬 MergeBeacon 的 Tauri/Vue/Rust 架构或固定限额

Slice 4 已产出：

- Local Git 的 list/file diff 通过唯一 adapter 投影 `GitPatchArtifact/v1[]`，并与 `electron/services/git-api.ts` 的可信 status 交叉核对；producer 超限或 status 缺失/不一致均降级为 `unavailable`，原始 patch 只保留为文本 fallback。
- Code Review 将 bounded raw patch 投影为共享 artifacts；producer `truncated` 或 malformed/unavailable 会在 Main 阻断模型调用，Renderer 通过四语 i18n 显示 fail-closed 原因。
- DCS `edit` 在成功 mutation 后投影共享 artifact，沿用 tool call `requestId`；Coding write journal 绑定同一 snapshot 的确定性 `journalEntryId`，request/path 不匹配时清空 artifact 并显式报错。
- diff extension 已审计但未跨包导入 ClawX root adapter：其发布包边界禁止逃逸相对导入；本切片不复制 contract/parser，也不扩张 public Plugin SDK。该 rendering 接线与富 diff 一并留给 slice 5。
- Electron Main 构建显式内联 ESM-only `@pierre/diffs`/`shiki`，避免打包后 CommonJS `require()` 启动失败；配置回归与目标 Electron E2E 已锁定。
- `slice-4-evidence.md` / `slice-4-gates.log`：48 个 root contract/adapter/consumer/config tests、54 个 runtime edit/journal tests、targeted ESLint、full typecheck、contract、i18n、comms、build、Code Review Electron E2E、Harness validate 与 `git diff --check` 证据。
- 可交付性状态：slice 4 evidence/log 与 slice 3 一样受 `artifacts/*` 忽略；未经授权未 stage，正式 change set 需显式纳入。

Slice 5 已产出：

- 全文件 `write` 在 mutation 后只使用 Coding write journal 的 before snapshot 与 workspace 中逐字节验证的 after content 生成真实 unified diff；producer 自报 patch 不受信。after mismatch、非 UTF-8、超限、无 request id、snapshot 数量异常或无实际变更均显式 fail closed。
- `edit` / `write` artifact 继续通过唯一 `adaptUnifiedDiffToGitPatchArtifacts` 生成并绑定同一 tool `requestId`、deterministic `journalEntryId` 与 repository-relative path；journal 仍是 mutation/snapshot/recovery/undo authority。
- Gateway chat display projection 只对白名单 `edit` / `write` 保留一个严格、complete、有界且与 journal snapshot 匹配的 `GitPatchArtifact/v1`；其他 tool details、working memory 与绝对 snapshot path 仍被删除。
- Chat 通过现有 `CodeDiff` 渲染 journal-backed patch，并用四语 Copy patch 操作复制同一个 artifact patch。Renderer 遇到 pending、missing、stale、truncated、unknown schema 或 lineage mismatch 时不回退到 baseline 推断。
- `slice-5-evidence.md` / `slice-5-gates.log`：26 个 root tests、50 个 runtime project tests、runtime/Vite build、真实 Gateway + scripted local provider Electron E2E、targeted ESLint、typecheck、contract/i18n/comms/Harness 与 `git diff --check` 证据。
- 可交付性状态：slice 5 evidence/log 受 `artifacts/*` 忽略；未经授权未 stage。`FP-P2-07` 保持 `in_progress`，下一且唯一下一切片为 slice 6 error envelope/redaction/negative tests。

Slice 6 已产出：

- `RemoteForgeError/v1` 现在强制 canonical `code/retryable/httpStatus/safeMessage` 组合与安全 request id；合法 schema 也不能夹带自定义用户可见消息。
- Git、Code Review、DCS edit/write journal 和 Renderer consumer 的 `patchArtifactError` 全部迁移到唯一 envelope；原始异常、stderr、响应体、绝对路径和 repository content 不进入该错误面。
- 反向测试覆盖 credential、Authorization、response body、repository content、private host、absolute path、oversize、unknown schema/code、invalid status/retryability/requestId，以及 nested/cyclic-looking payload。
