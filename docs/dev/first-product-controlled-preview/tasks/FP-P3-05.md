## Goal（用户可见结果）
E2E / 打包永远测的是当前源码编译出的 gateway，而不是过期的 `openclaw_runtime/dist/entry.js`。

## Why this exists
FP-P0-06 首跑 E2E 时，`openclaw_runtime/dist/entry.js` 是 schema 修复之前构建的旧 bundle，
E2E 实际测到了旧代码（gateway child 拒绝配置退出），造成一次假失败。gateway 启动路径
`electron/utils/paths.ts:204`（getOpenClawRuntimeEntryPath）优先取 dist；runtime src 改动后
若不重建，E2E 与手工验证都会静默测旧 bundle —— 反过来也可能造成**假成功**。

## 实现要点
1. 守卫形式二选一：E2E fixture 启动前比对 `openclaw_runtime/src` 与 `dist` 的 mtime/hash，
   过期即 fail-fast 并提示 `pnpm build:runtime`；或在 `test:e2e:run` 前挂轻量脚本。
2. 打包链（`pnpm build` / `package`）已含 build:runtime，不受影响；守卫只针对直接跑 E2E 的路径。
3. 反向验证：touch 一个 runtime src 文件不重建 → E2E 启动即报过期。

## Acceptance criteria
- [ ] E2E 在 dist 过期时 fail-fast 且报错可读（指出重建命令）
- [ ] dist 新鲜时零额外开销（或 <2s）
- [ ] 反向验证贴输出
