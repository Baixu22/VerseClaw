## Goal（用户可见结果）
`docs/dev/default-config-matrix.md` 的「Product default」一列被逐格锁定：任何人把某格从
`false` 改成 `true` 而不改实现，CI 立刻红。

## Why this exists
`FP-P0-03` 已做到「md 每个 surface 行都有断言」，但 `MD_MATRIX_ROWS.declaredDefault`
目前只是 fixture 里的**标注**，没有与 md 单元格文本逐字比对 —— 只有 VToken 行比对了
`**false** (opt-in)`。也就是说：有人把 md 里某行的默认值文字改掉，测试不会发现，
文档与实现可以静默漂移，而 md 是本 program 声明的 SoT。

## Non-goals
- 不改 matrix 内容
- 不扩展 matrix 覆盖面（那是 FP-P0-03 已完成的部分）
- 不做 md → 代码的自动生成

## Context / code anchors
- `docs/dev/default-config-matrix.md`（表格第 3 列 = Product default）
- `tests/fixtures/launch-contract-matrix.ts` → `MD_MATRIX_ROWS.declaredDefault`
- `tests/unit/default-config-matrix.test.ts` → describe `FP-P0-03 md row coverage`

## 实现要点
1. 解析 md 表格第 3 列（注意单元格内含 `**` 与括注，如 `**false** (opt-in)`、`**false** (deny)`）。
2. 与 `declaredDefault` 逐行比对；不一致即失败并打印 md 原文与 fixture 值。
3. 同时校验实现侧默认值与 `declaredDefault` 一致（三方一致：md ↔ fixture ↔ 代码）。
4. 反向验证：临时改 md 一格 → 测试失败。

- [x] 三方一致（md ↔ fixture ↔ 实现默认值）→ 每行实现探针（DEFAULT_* 常量 + resolver 空配置行为）与 `declaredDefault` 比对，探针缺行即失败
