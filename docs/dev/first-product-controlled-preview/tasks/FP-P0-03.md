## Goal（用户可见结果）
启动契约被测试冻结：任何人再把某个增强的默认值偷偷翻成 ON，或让 kill 在某条路径失效，CI 立刻红。

## Why this exists
`FP-P0-01` / `FP-P0-02` 修的是两处已发现的漂移。没有回归门禁，同类漂移会再次发生（历史已发生过至少两次：VToken env、Assembler cfg）。启动层是唯一同时被 Electron、config-sync、runtime resolver 三方写入的地方。

## Non-goals
- 不新建测试框架
- 不追求覆盖全部 flag，只覆盖 `default-config-matrix.md` 登记项
- 不做性能/soak

## 测试矩阵（最小集）
| 维度 | 用例 |
|------|------|
| 默认 | 无 env、无 config、无 Settings → 每个登记项等于 matrix 声明值 |
| opt-in | 单一来源启用 → child effective 为 ON |
| kill env | `=0/false/off` 覆盖任何启用来源 |
| kill config | `contextEnhancement.killSwitch=true` 覆盖任何启用来源 |
| 双 kill | 同时打开 → 仍然 OFF，无异常 |
| 冲突 | Settings ON + env kill → OFF（kill 胜） |
| 异常 | config 不可解析 → fail-closed |

## 机器可读来源（slice 1 裁定）

`default-config-matrix.md` 的表格是给人读的（"How to enable" 一列是自然语言），
无法直接机器执行。按任务书授权的 **「matrix 不可机器读取就加 fixture 并断言与 md 同步」**
路线：`tests/fixtures/launch-contract-matrix.ts` 提供两份机器可读结构，
测试**遍历**它们而非手写枚举：

| 结构 | 作用 | 同步守卫 |
|---|---|---|
| `MD_MATRIX_ROWS`（10 行） | md 每个 surface 行 → 声明默认值 + 负责断言的 tag | ①测试用正则从 md 提取所有加粗 surface 行，任何 md 行未登记 → 失败；②每个 `assertedBy` tag 必须真实出现在测试标题里，否则 → 失败 |
| `LAUNCH_CONTRACT_MATRIX`（9 行） | 启动层 × resolver 的交叉积（unset / 显式 on / 显式 kill × config opt-in × Settings） | 每行同时断言 child env 与 resolver 两侧；md 覆盖行必须有 ≥1 用例 |

反向验证（证明守卫非空转）：临时从 `MD_MATRIX_ROWS` 删掉 `VToken bridge` 一行后实跑，
测试报 `md rows with no assertion registered ...: VToken bridge` 并 **1 failed**，已恢复。
