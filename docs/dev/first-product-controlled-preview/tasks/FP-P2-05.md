## Goal（用户可见结果）
改完文件后，相关测试自动跑一遍，结果（通过 / 失败 / 跳过原因）出现在会话里，
用户不必自己想起来去跑。

## Why this exists
`FP-P1-04` 补齐了 verify 段缺失的一半 —— **探测**（`test-runner-detect.ts`：
node/pytest/cargo/go，skip 必带 reason）。但**执行**仍靠模型自己想起来调 exec/bash。
探测结果目前只作为文本提示出现在工具结果里。

FP-P1-04 的裁定是「只探测不执行」，理由是执行应继承 exec 工具既有的审批 / 沙箱 / 超时策略，
不在写路径上新开第二条执行通道。本任务在**不违反该裁定**的前提下做自动触发。

## Non-goals
- 不在 `write-side-effects` 里直接 spawn 进程（违反 FP-P1-04 裁定）
- 不做测试结果的智能分析 / 自动修复

## Context / code anchors
- `openclaw_runtime/src/agents/test-runner-detect.ts`（探测，已实现）
- `openclaw_runtime/src/agents/write-side-effects.ts`（`verify_tests` 附加点）
- exec / bash 工具的审批与超时策略（开工时列出精确路径）

## Acceptance criteria
- [ ] 探测到 runner 后能自动触发一次测试执行，且**走 exec 工具的既有审批 / 沙箱 / 超时策略**
- [ ] 执行结果（pass/fail 计数或原始尾部输出）回填进会话可见输出
- [ ] 失败不阻断写入，但必须显式可读（不静默）
- [ ] 超时 / 被审批拒绝 / runner 崩溃三类情况各有可读结论
- [ ] 探测扩展：monorepo 子包（就近 package.json）、自定义 runner 配置
- [ ] 可显式关闭；默认行为需在 `docs/dev/default-config-matrix.md` 有一致声明
