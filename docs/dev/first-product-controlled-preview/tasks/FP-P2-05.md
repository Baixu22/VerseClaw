## Goal（用户可见结果）
改完文件后，相关测试自动跑一遍，结果（通过 / 失败 / 跳过原因）出现在会话里，
用户不必自己想起来去跑。

## Why this exists
`FP-P1-04` 补齐了 verify 段缺失的一半 —— **探测**（`test-runner-detect.ts`：
node/pytest/cargo/go，skip 必带 reason）。但**执行**仍靠模型自己想起来调 exec/bash。
探测结果目前只作为文本提示出现在工具结果里。

FP-P1-04 的裁定是「只探测不执行」，理由是执行应继承 exec 工具既有的审批 / 沙箱 / 超时策略，
不在写路径上新开第二条执行通道。本任务在**不违反该裁定**的前提下做自动触发。

## Non-goals
- 不在 `write-side-effects` 里直接 spawn 进程（违反 FP-P1-04 裁定）
- 不做测试结果的智能分析 / 自动修复
