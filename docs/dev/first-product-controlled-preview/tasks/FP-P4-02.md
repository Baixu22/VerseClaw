## Goal（用户可见结果）
用户能让 agent 在监督下完成一个有目标的浏览器任务，任务开始前有审批，结束时有成功判定；私网仍然被拒。

## Why this exists
私网 deny、Vault、approval/recovery backend 已有（前序 `TASK-P1-06` done），但 UI 直接 `createTask → runTask`，executor 主要只打开 URL，未真正执行 objective / success condition。也就是「安全壳完成、能力未完成」。

## Non-goals
- 不做无监督模式（**硬锁**）
- 不放开私网访问（**硬锁**）
- 不进 Controlled Preview 首发范围

## Implementation slices
1. **contract + audit**：固定 approval、step、verification 与 redacted evidence 合约；确认 Renderer 仅经 host-api，逐跳复核私网 deny 与 Vault 边界。
2. **approval control plane**：新任务默认进入 `waiting-approval`，审批面展示 objective、目标站点、allowed domains、mode 与动作范围；拒绝不启动 session。
3. **objective executor**：Main 按有界、可取消的步骤计划执行 `navigate` / `wait-for-selector` / `click` allow-list，不再只打开 URL；每步复核目标域、网络请求与 runtime 开关。
4. **success verification + observability**：输出 typed success/failure reason、逐步 lineage/counter 与脱敏 evidence；失败保持可解释、可重试。
5. **UI + i18n**：Browser workbench 补审批、运行步骤、成功判定和失败信息；覆盖 en/zh/ja/ru 与既有 design token。
6. **verification**：单测 happy/failure/deny/kill，Electron E2E approval→多步→成功/失败，公网 fixture soak，contract/harness/comms/full gates。

## Residuals
- 真人 10 次使用记录降级为 engineering-validation-only；若未来引入外部 reviewer，需补真人 G4 证据与 safetyReviewer 签字。
- 无监督模式与私网访问永久硬锁不解除。
- popup deny 使用固定脱敏消息，不持久化页面生成 URL；实际请求拦截改用 Electron session `resolveHost()` 结果复核私网/特殊地址。`onBeforeRequest` 仍不能提供传输层 IP pinning，连接时 DNS 绑定属于显式安全残留，策略继续 fail closed。
- synthetic soak、E2E 与截图均为 fixture-grade；不存在真人、真实公网、clean VM、真实凭据或产品审批证据。
- FP-P4-02 evidence 目录受仓库通用 `artifacts/*` ignore 规则影响，当前文件存在于本地但不会出现在普通 `git status`；后续获准提交时必须显式纳入，不能遗漏或冒充已 tracked。
- repository `git diff --check` 与 Harness diff-coverage 均已通过；前序 system-maturity、P3→P4 阶段文档和继承 P0/P1 测试差异已分别形成累计 checkpoint，不再污染本任务增量。P4-02 evidence 已显式纳入 checkpoint。
