## Goal（用户可见结果）
一条自动化测试代表「新用户第一天」：clean install → provider verify → model verify → workspace select → DCS enable → 真实编码请求 → 读上下文 → 改文件 → diff/test → undo → restart → recovery，全程通过。

## Why this exists
`FP-P1-01..06` 各自有测试，但首产品的承诺是**连起来**能走通。没有这条串行 E2E，任何一次重构都可能悄悄断掉链路中间一段。这是 `FP-P1` 的出口门禁。

## Non-goals
- 不追求覆盖所有 Provider 厂商（选一个代表）
- 不做性能基线
- 不替代真人 canary（`FP-P2-02`）

## 已知障碍（开工先解）
`VERSE_CLAW_E2E` 会跳过 gateway auto-start（见前序 `TASK-P0-01` honesty note）。本任务必须在**真 gateway 启动**下跑，否则 ack 与工具目录都无法验证。方案二选一并写入本文档：
- **A** 新增 E2E profile：真 gateway + 假 Provider 端点（本地 mock server，非 mock 代码路径）
- **B** 保留真 Provider，标记为 `@live` 套件，不进默认 CI，但每次 phase 出口必跑

4. Gateway 未就绪
5. workspace 无权限
6. approval / kill 之后的失败
