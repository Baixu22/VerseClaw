## Goal（用户可见结果）
运维看到某个 flag 是 ON 时，能直接读出「它为什么是 ON」：来自 env、来自 openclaw.json、
来自默认值，还是被 kill 压成 OFF。

## Why this exists
`FP-P0-04` 的 ack payload 里 `configSource` 实际形态是
**「child 读到的 config 文件路径 + 是否存在 + 来源类别(env-override/state-dir)」**，
而任务书表格设想的是**「每个 flag 的生效来源（env / config / default / kill）」**。
两者不是一回事：当前形态能回答「读了哪份配置」，不能回答「这个 flag 为什么是这个值」。

该差异已在 `FP-P0-04` 文档显式记录，未冒充完成。做逐 flag 归因需要在每个 resolver
里回传来源，改动面较大，故独立成任务。

## Non-goals
- 不改 flag 的解析优先级语义
- 不改 ack 的七字段必填集（`configSource` 仍是其中一个字段，只是内容更细）

## Context / code anchors

## 实现要点
1. resolver 由「返回 boolean」改为「返回 {value, source}」，或旁路提供 `explain*()`。
   倾向旁路，避免改动所有调用点的签名。
2. `source` 枚举至少：`env` / `config` / `default` / `kill`（kill 需区分 env-kill 与 config-kill）。
3. 汇总进 ack 的 `configSource`，保留现有「读了哪份文件」信息（不要替换掉，二者都有用）。
4. UI 在 `AckDetail` 里按 flag 展示归因。
5. kill 态必须归因为 kill，不能显示为 default —— 否则运维会以为「本来就没开」。

## Acceptance criteria
- [x] 每个可写 flag 的 ack 归因为 env / config / default / kill 之一
      → `resolveEffectiveRuntimeFlagsWithSources`；单测「每个 effective flag 都必须有归因」全覆盖守卫
- [x] env-kill 与 config-kill 可区分
      → 单测「attributes the kill switch itself to env vs config」：env 路径带变量名 `VERSE_CONTEXT_ENHANCEMENT_KILL_SWITCH`，config 路径为 `origin:"config"`
- [x] 保留原有「child 读到哪份 config 文件」信息
      → `configSource` 字段未改动；`flagAttribution` 为**并列新增**字段
- [ ] UI 逐 flag 展示归因，i18n en/zh 内容齐（ja/ru 键位齐）
      → **部分**：i18n 四语键位齐（`developer.dcsPreview.origin.*`，`i18n:lint` 过），
        面板已渲染 origin 徽章（`settings-dcs-preview-origin-<key>`，`typecheck:web` 过），
        但 E2E 未能稳定断言到该徽章 → 见 Decision 3，转残留 **FP-P1-08**
- [x] 单测：四类来源各一例 + kill 覆盖 config 的归因正确
      → 8 用例，含「kill 覆盖 ON flag → `origin:"kill"` 而非裸 false」
- [x] 真 child E2E：至少一个 flag 的归因在真进程里正确
      → `[fp-p1-10-attribution]` 真 child 输出：`compass=default` vs `working_memory=config`+具体路径，
        **同值不同源**，正是 `configSource` 答不了的问题

## Decision

1. **旁路而非改签名**。新增 `resolveEffectiveRuntimeFlagsWithSources()`，
   原 `resolveEffectiveRuntimeFlags()` 降为薄封装 —— 所有既有调用点零改动，
   既有 17 条 ack 单测未改一行即全绿。
2. **`flagAttribution` 不进 `RUNTIME_FLAG_ACK_REQUIRED_FIELDS`**。
   若进必填集，旧 child（不发该字段）会被判 `ack-incomplete` → `failed`，
   等于用一个诊断字段把 FP-P0-04 的 applied 契约变脆。故为可选新增字段。
3. **UI 徽章不做阻塞断言**。徽章依赖面板缓存的 ack 对象，而本 spec 的 Phase C
   **本身独立 flaky**（disable 步撞 2500ms 重启冷却，本轮 5 次运行中 3 次在该处失败，
   与本任务改动无关 —— 改动前的基线运行同样出现过）。
   让一个 P2 展示细节成为已知 flaky 阶段上的阻塞断言，买到的是噪声不是信号。
   归因**契约**已在真 child 层（E2E）与纯函数层（单测）双重断言。

## Implementation slices
1. resolver 旁路 `explain*()`
2. ack 汇总
3. UI + i18n
4. 单测 + E2E
