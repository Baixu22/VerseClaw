## Goal（用户可见结果）
基于 P2 GitHub canary 和 P3 发布证据，决定是否扩到 GitLab、Gitee、stacked PR dependency DAG 和 Merge Queue/Train 只读状态，避免为能力矩阵盲目扩面。

## Non-goals
- 本任务不实现 GitLab/Gitee adapter
- 不自动创建 stacked PR 或调整分支
- 不实现 Issue/release/project 管理

## 裁决输入
- `FP-P2-08` 只读完整性与错误率
- `FP-P2-09` review mutation、stale guard 和 approval 证据
- `FP-P2-10` readiness/merge 工程证据
- `FP-P2-02/03` 真人 canary 与联合裁决
- `FP-P3-03/04` clean VM、发布和运营成本

## Acceptance criteria
- [ ] 对 GitLab、Gitee、PR DAG、Queue/Train 分别给出 continue/shrink/stop
- [ ] 每个 continue 项有用户需求、平台 API、权限、维护成本和安全边界证据
- [ ] PR DAG 若继续，保留 repository identity、cycle、truncated 和 blocking parent 语义
- [ ] Gitee 若继续，明确禁止 query token 进入日志/通用 URL
- [ ] adapter 实现拆成独立 Task Forest proposal，经确认后才 apply
- [ ] stop/shrink 项记录复审触发条件，不留无限期模糊 backlog

## Implementation slices
1. 使用和成本数据汇总
2. 平台能力/权限复核
3. DAG/Queue 产品需求验证
4. continue/shrink/stop 与候选 proposal
