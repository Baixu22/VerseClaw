## Goal（用户可见结果）
注入预算的总额与告警线由真实使用数据决定，不再是拍的数；运维能按环境调整而不必改代码。

## Why this exists
`FP-P0-05` 裁定了两个数：`TURN_INJECTION_CHAR_BUDGET = 6000` 与
`TURN_INJECTION_DROP_ALERT_RATIO = 0.1`。两者都在该任务 `## Decision` 里被显式标注为
**起始线、非经验值**，且当前是导出常量（改需改码，只有 `beginTurnInjectionBudget` 的
`total` 参数可覆盖）。

只有等 `FP-P2-02` 的 ≥10 次真人 DCS coding 任务产出真实分布，才能判断 6000 是否够、
10% 是否太松或太紧。

## Non-goals
- 不改 precedence 顺序（`FP-P0-05` 裁定）
- 不改 drop/truncate/skip 语义
- 不新增注入源

## 实现要点
1. 从 `FP-P2-02` 的真人任务里导出每轮 `requestedChars` / `appliedChars` /
   `droppedChars` / `truncatedChars` 分布（p50 / p90 / p99）。
2. 依分布定总额：目标是 p90 不触发降级，而不是「p100 不降级」（后者等于取消预算）。
3. 依分布定告警线：告警应当稀有但非零 —— 若真实 drop 率长期为 0，说明预算过松，
   应**收紧总额**而不是降低告警线。
4. 配置化：openclaw config `runtime.contextBlock.injectionBudget.{totalChars,dropAlertRatio}`
   （**注意**：新增 config 叶子必须同时补 `zod-schema.ts`，见 `FP-P0-06` 的教训）。
5. 分布数据与最终取值理由入档。
