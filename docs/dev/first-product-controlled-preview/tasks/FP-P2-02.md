## Goal（用户可见结果）
把 L3 从 0 变成 ≥10：真人在产品 UI 内完成 10 次真实编码任务，并在同一版本和 charter 下消费 GitHub Forge read/review/merge 受控能力，回答「编码闭环和远端协作到底好用吗、安全吗」。

## Why this exists
这是整个 program 里唯一无法用工程手段替代的证据。当前 `artifacts/dcs-deep-test-week1/runs/` 6 个 run 全部 `notHumanProductChat=true`。新增 Forge 的自动化只能证明 contract/policy 存在，不能证明真人能理解完整性提示、审批、stale-head 拒绝和 merge 后果。

## Non-goals
- 不做 A/B 对照实验设计（`TF-0006` 范畴）
- 不做 soak（长时压测另立任务）
- 不解阻 `TF-0006`
- 不因结果好就翻默认
- 不扩到 GitLab/Gitee、PR DAG 或生产仓库 merge

## 硬性口径
- **真人**：由 charter 中的 `operator` 本人在产品 UI 内发起，非 agent 自动跑、非脚本回放。
- **产品任务**：真实工作需求，不是「测试一下」的人造样例。
- `notHumanProductChat` 必须为 `false`，否则该次不计数。

## 每次任务必须记录
| 字段 | 说明 |
|------|------|
| `taskId` | canary 内序号 |
| `operator` | 执行人 |
| `requestSummary` | 需求一句话（脱敏） |
| `lineage` | request / session / workspace |
| `flags` | 本次 effective flags + 来源 |
| `tokens` / `latency` | 用量 |
| `toolStats` | hit / drop / truncation |
| `errors` | 出现的错误 |
| `outcome` | 成功 / 部分 / 失败 |
| `didRollback` | 是否 rollback 及原因 |
| `undoUsed` | 是否 undo、是否 100% 成功 |
| `forgeActivity` | `none/read/review/metadata/merge`；允许一项或多项 |
| `forgeRepository` | 脱敏 repository 标识，必须在 charter scope 内 |
| `forgeHeadSha` | 远端动作绑定的 head SHA；无动作时为空 |
| `forgeCompleteness` | complete/incomplete/unknown 及原因 |
| `forgeApproval` | 是否触发 action-bound approval、是否单次消费；不得记录 secret |
| `forgeOutcome` | 成功/被策略阻断/平台失败/部分成功及 reason code |
| `notHumanProductChat` | 必须 `false` |
