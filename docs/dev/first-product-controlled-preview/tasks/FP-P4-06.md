## Goal（用户可见结果）
阅读任何一份仓内文档都不会把历史上的「VToken assembly 默认开启」误认成当前 authority；
当前 spec、注释和权威矩阵全部明确 default OFF，历史原文仅在相邻勘误下保留。

## Why this exists
`FP-P0-01` 把启动层的 `VERSE_VTOKEN_ASSEMBLY_ENABLED` 强注删净，产品默认恢复为
`false (opt-in)`，与 `docs/dev/default-config-matrix.md` 一致。

实施前，前序 program 的 `docs/dev/dcs-visible-production/tasks/TASK-P1-04.md`
仍有两处未勘误的「default 1 / default on unless killed」历史描述。

`FP-P0-01` 的 Non-goals 明确不改前序 program 文档（避免跨 program 越界改历史记载），
故登记为残留。留着的风险是：后来者读到前序文档会以为默认 ON，据此写出错误的 baseline 结论。

## Non-goals
- 不改前序 program 的进度/结论（只勘误事实性描述）
- 不重写 `dcs-visible-production` 的 STATUS
- 不改运行时默认值、启动 env、配置 precedence 或 kill 行为（仅修正两处开发者注释）

## 实现要点
1. 全仓扫一遍，不要只改已知那两行：
   `grep -rn "VERSE_VTOKEN_ASSEMBLY_ENABLED" --include=*.md`，
   再查「default ON / 默认开启 / 默认 1」等表述。
2. 勘误方式：**保留历史记载 + 加勘误注**，而不是直接改写历史结论
   （前序 program 当时的描述反映了当时的代码状态，直接改写会丢失「曾经漂移过」这个事实）。
3. 勘误注需指向 `FP-P0-01` 与 `default-config-matrix.md`。
4. 同时检查 `packages/vtoken/README.HOST.md`、`harness/specs/rules/vtoken-foundation-boundary.md`
   等是否有同类表述。
