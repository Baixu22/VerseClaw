## Goal（用户可见结果）
只有当前 PR 版本同时满足 branch protection、CI、冲突、审批、讨论、权限和本地 action-bound approval 时，ClawX 才允许合并；结果可审计、不可误复用。

## Non-goals
- 不自动关闭 Issue
- 不自动进入 Merge Queue/Train
- 不把 MergeBeacon 的近似 approval-ready 逻辑直接作为硬门禁

## Acceptance criteria
- [ ] readiness 使用 `ready/blocked/pending/unknown` 和稳定 reason codes
- [ ] `unknown`、数据不完整、分页失败、head SHA 缺失一律禁止 merge
- [ ] Main policy 在执行前强制重新获取 readiness，不依赖 UI 先调用
- [ ] approval 绑定 provider/repo/pr/headSha/strategy/readinessDigest/payloadDigest，且有时效与单次消费
- [ ] approval 后 head、策略或 readiness 变化会使审批失效
- [ ] merge API 携带 expected head SHA；冲突/409 返回稳定需刷新语义
- [ ] merge 主效果与后续刷新/审计失败分离，不能把已合并显示为失败后重试
- [ ] 自动化覆盖 ready、CI pending/failed、draft、conflict、behind、stale approval、权限不足
- [ ] readiness/approval/merge UI 文案覆盖 en/zh/ja/ru；Renderer 不持有 readiness 或 merge policy
- [ ] 开工前把 hard-veto、审批失效和受控 merge 更新到共享 Harness task spec
- [ ] 默认 Agent merge 保持关闭；真人矩阵与 continue/shrink/stop 归 `FP-P2-02/03`
