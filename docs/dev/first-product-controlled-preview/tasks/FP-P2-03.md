## Goal（用户可见结果）
canary 结束后，DCS coding、Forge read、Forge review、Forge merge 四个能力面分别得到 continue/shrink/stop 裁决；全仓账目与分面结论一致，不用一个总的 continue 掩盖 merge 风险。

## Why this exists
历史上多次出现「多份文档各说一套」（如 C1 决策 5.125x vs report 4.5x）。裁决点必须有唯一出口，并把账目一次性对齐，否则下一轮又要重新考古。

## Non-goals
- 不做 default-on 毕业决策（那需要 productApproved + TF-0006）
- 不解阻 `TF-0006`
- 不改代码
- 不因 GitHub continue 自动扩到 GitLab/Gitee/PR DAG

## 裁决输入
- `FP-P2-07` 来源/patch/error contract 证据
- `FP-P2-08` GitHub 只读完整性与错误率
- `FP-P2-09` review mutation、stale guard、partial success 与审批证据
- `FP-P2-10` readiness/merge hard-veto 工程证据
- `FP-P2-02` 10 次 DCS + Forge 真人联合记录与达标情况
- `FP-P2-04/05/06` 预算、verify 和逐通道归因收口证据
- `FP-P1-05` live kill/rollback 证据
- 成本与预算实际消耗
- safetyReviewer 复核结论
- 出现的 bug 清单（已转任务）

## 裁决规则（写死，不许临场解释）
| 条件 | 裁决 |
|------|------|
| 某能力面全部硬指标达标 + 无 stop condition 命中 | 该能力面 `continue` |
| 某能力面安全达标但价值不明显、成本过高或覆盖不足 | 该能力面 `shrink` |
| 某能力面任一 stop condition 命中且未修复 | 该能力面 `stop` |
| DCS 记录 <10、Forge 消费/阻断矩阵不足或字段缺失 | 不得裁决，回 `FP-P2-02` |
| Forge merge 为 shrink/stop | read/review 可独立 continue；默认 Agent merge 保持 OFF |

## Hard locks
