[P1] Unsupported source claims still drop all open-mode claims including unrelated supported/general claims
electron/services/knowledge-evidence-qa.ts:152
In `applyKnowledgeSupportReview`, open mode only filters individual source claims when their own verdict is not `supported`, but the return branch ignores `review.answerability` entirely. If the judge reports `answerability: 'insufficient'` for one source claim while also returning a supported general claim (a case explicitly covered in this patch's tests), open mode keeps the general claim but removes the supported source claim as well. More importantly, “missing/conflicting evidence becomes unknown” applies to strict mode, while open mode should preserve supported source claims and uncited general/inference claims. Use the judge's per-claim verdicts for source claims and only use `answerability` to add unknowns in open mode; reserve clearing the whole claim list for strict mode.

[P1] Quote presence alone is treated as exact quotation correctness without checking whether the quote is complete or unambiguous
electron/services/knowledge-evidence-qa.ts:101
`bindKnowledgeQaClaims` verifies that the model-provided `quote` occurs somewhere in the source content and then marks `exactQuote: 'verified'` and `sourcePin: 'verified'`. It does not require the quote to be a complete sentence or a minimal/exact excerpt, and it does not ensure the selected occurrence is the intended one when the same substring appears multiple times. This is a concrete contract gap for “exact byte-bound citations”: a model can quote a tiny fragment (e.g. `port`, `18789`, `yes`) that satisfies the byte check while not being a meaningful or uniquely attributable source span, and the result is still surfaced as verified exact quote + pin. At minimum reject quotes that are not a contiguous, unambiguous span or require a minimum semantic granularity before claiming exact quotation verification.

[P1] Source citation navigation does not request the raw citation range
src/pages/Knowledge/index.tsx:1048
The UI routes an answer citation to `openResult`, but `openResult` always calls `knowledge.get` with a fixed `lineCount: 120` and never passes `fromLine` or a range derived from `sourceRef.locator`. The new preview only prints `Raw source lines X–Y` after the owner read returns, so clicking a citation opens the beginning of the file rather than navigating the owner-checked raw range. For a citation in a later part of a long document, the quoted text will not be visible, which breaks owner-checked raw citation navigation. Pass a line window around `sourceRef.locator.startLine`/`endLine` (or a dedicated citation-read API) and render the requested span.

[P1] Open-mode source claims with no admitted sources are sent to the model without owner/DCS references
electron/services/knowledge-api.ts:3464
The new open-mode branch allows synthesis when `sources.length === 0`. It then still calls `runKnowledgeModel` with `sessionKey` omitted (because `sessionKey` is only required when sources exist) and no `knowledge` object. That means a supposedly read-only Knowledge answer can run through the general model path with no owner-bound evidence. Open mode is supposed to allow general knowledge and inferences with empty citations, while source-backed claims remain tied to admitted sources. This path has no marker distinguishing “no source answer” from a normal model-only session, and the prompt still instructs source claims to cite exact refIds. A model can hallucinate a source claim, but validation will fail; more importantly, the call is not constrained to the Knowledge model-only/read-only path for the empty-source case. Route empty-source open answers through an explicit model-only open path that forbids source citations and records that no DCS references were used.

overall: patch is incorrect (0.88)
The main contract wiring is present: strict/open modes exist, quote/pin checks are separate from claim support, and owner reads are rechecked after both model calls. The patch still has correctness gaps: open-mode review drops supported source claims on a single insufficiency verdict, exact quote verification is weaker than the stated byte-bound citation contract, citation navigation ignores the requested raw range, and empty-source open answers bypass the explicit Knowledge model-only path.
