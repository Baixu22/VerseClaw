# Repository Dead-Code and Artifact Audit

Audit date: 2026-08-13

Scope: tracked Git tree plus the current local workspace. This is a read-only audit; no product or source files were removed.

## Executive result

- Git tracks about 18,256 files. `openclaw_runtime` is the dominant source tree: 11,786 tracked files. It is a real runtime dependency, not a cleanup candidate.
- Renderer reachability is healthy at the page level: `src/App.tsx` owns the route graph and lazy-loads the current pages. The audit found no large set of pages that are only present on disk and absent from the route graph.
- `src/components` contains 164 TypeScript/TSX files. A filename-only scan is not sufficient to call these dead: barrel exports, generated extension bridges, tests, route registries, and dynamic imports are all present.
- The largest cleanup opportunity is generated/local data, not production source: `.codegraph` (~461 MiB), `resources/bin` (~172 MiB), `openthoughts-tblite` (~49 MiB), `openclaw_runtime/.artifacts` (~44 MiB), `dist` (~27 MiB), `dist-electron` (~23 MiB), runtime codegraph dist (~18 MiB), and `jobs` (~7 MiB). These are local/build/evidence assets and are already ignored or intended to be regenerated in the normal workflow.
- The tracked tree has substantial evidence/document duplication. `artifacts` has 1,136 tracked files; `.agent-workbench` has 159; `runtime-research` has 731 Markdown files; `reports` has 84 files; `docs` has 255 files. These are not all dead, but many are historical snapshots rather than runtime inputs.

### C. Compatibility or optional assets: not dead by filename

- `openclaw_runtime/` is the bundled OpenClaw runtime and is built by `scripts/build-openclaw-runtime.mjs`; removing it breaks the app.
- Channel packages such as Feishu, WeCom, DingTalk, QQBot, WhatsApp, and Baileys are optional runtime integrations. They are imported/installed dynamically or mirrored into the runtime; a static direct-import scan incorrectly labels them unused.
- `resources/skills/preinstalled/` contains repeated Office schema/validator trees for different file formats. The duplicates are intentional packaging inputs for DOCX/PPTX/XLSX, not generic dead code.
- Root configuration files (`vite.config.ts`, `electron-builder.yml`, TypeScript/Vitest configs, `postcss.config.js`, `components.json`, `clawx-extensions.json`) are all referenced by scripts, workflows, or runtime loaders. No root config was proven unused.

## Dead-code findings

### Confirmed or near-confirmed candidates

1. `dcs-review-glm-output/`: 4 tracked review files, no references outside the directory. Treat as external review archive; delete only after policy confirmation.
2. `brandnew/`: one planning Markdown file, no product/runtime references. Archive/delete candidate.
3. `scripts/chain-audit/analyze-jforum-fix.mjs`, `score-coding-dimensions.mjs`, `verify-compaction.mjs`, and `scripts/generate-p45-final-evidence.mjs`: no package-script or repository-text callers were found. They are specialized historical/evaluation tooling, not application code. Move to an explicit `scripts/archive/` or remove after confirming no external operator invokes them.
4. Duplicate tracked evidence: repeated `final-validation.log` files under `artifacts/system-maturity/P4-*`/`P5-*`, repeated `PR-FULL` logs, duplicate `COMPLETE.md`/`REPORT.md`, and duplicate Task Forest export files. Keep one canonical artifact and regenerate/reference it through the owning tool.

### Retired feature chain requiring migration, not blind deletion

The old Work Mode surface is explicitly hidden from current Chat UI and current ordinary chat payloads, but it is not isolated:

- `src/components/chat/WorkModeSummaryPanel.tsx` is only used by its unit test, yet its types/configuration are still consumed by `shared/types/work-mode.ts`, `shared/types/work-provider.ts`, settings persistence, and compatibility tests.
- Work Mode locale blocks remain in all four locales.
- E2E/unit tests intentionally assert that the old UI stays hidden and that legacy fields are ignored.

Conclusion: this is a deprecated compatibility chain, not a safe one-file deletion. Remove it only as a coordinated migration: persist/migrate old settings, remove compatibility tests, then remove the panel, locales, types, and settings keys together.

## Dependency/configuration observations

A static package-import scan reported possible unused direct dependencies, but several are false positives because the runtime loads optional plugins and build tools dynamically. The following deserve a deliberate dependency review, not immediate removal:

`@ast-grep/napi`, `@lobehub/assets-fileicon`, `react-virtuoso`, `@radix-ui/react-radio-group`, `@radix-ui/react-toast`, `autoprefixer`, `cheerio`, `electron-builder`, `exceljs`, `https-proxy-agent`, `opusscript`, `postcss`, `qrcode-terminal`, and `react-is`.

The package manifest and lockfile still contain actively referenced optional channel/provider packages. Use a package-aware tool (Knip or equivalent) plus build/test verification before changing `package.json` or `pnpm-lock.yaml`; this audit did not modify them.

## Recommended cleanup sequence

1. Reclaim local generated directories in section A when no build/test process is running. This is the fastest way to recover roughly 0.8 GiB of workspace space.
2. Create a retention policy for `artifacts/`, `reports/`, and `runtime-research/`: keep canonical summaries, release manifests, and evidence required by current harness specs; archive raw stdout/stderr/logs after a fixed period.
3. Use the Task Forest CLI to prune or archive old snapshots/exports. Do not hand-edit `.agent-workbench/task-forest/`.
4. Archive `dcs-review-glm-output/`, `brandnew/`, `prototypes/`, and `.design-staging/` in separate reviewed commits; update any release manifest or docs references before removal.
5. Remove or archive the four uncalled chain-audit scripts after checking external operator runbooks.
6. Plan a dedicated Work Mode compatibility retirement change. Do not mix it with evidence cleanup.
7. Add Knip (or an equivalent package-aware unused-export/dependency check) to a review branch and validate candidate dependency removals with `pnpm run typecheck`, `pnpm test`, `pnpm run build:vite`, and the relevant Electron E2E gate.

## Limitations

This report intentionally does not claim that every unreferenced export is dead. Electron IPC channels, dynamic imports, generated extension bridges, optional plugins, tests, and release manifests create non-local references. The safe deletion set is therefore smaller than a filename/grep result, while the archive candidates above are supported by both reference scans and project policy.
