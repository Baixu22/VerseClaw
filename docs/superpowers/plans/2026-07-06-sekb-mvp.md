# SEKB-MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the runtime-side self-evolving knowledge base MVP: L3 trajectories, L2 principles, bounded L1 index, advisory retrieval, and manual distillation.

**Architecture:** SEKB lives under `openclaw_runtime/src/knowledge/sekb/` and persists global runtime knowledge in the shared OpenClaw state SQLite DB. It exposes small TypeScript classes that can be wired into the custom OpenClaw agent runtime later without adding LangChain, LlamaIndex, a vector DB, or autonomous correction behavior.

**Tech Stack:** TypeScript ESM, Vitest, `node:sqlite`, existing OpenClaw state DB schema, generated Kysely table types, sync Kysely SQLite helpers.

## Global Constraints

- Reuse the self-developed OpenClaw runtime; do not introduce LangChain or LlamaIndex.
- Use runtime-side SQLite/OpenClaw persistence patterns; do not add a required external DB.
- Keep embeddings optional and nullable; lexical retrieval must work deterministically when embeddings are absent.
- Renderer/Main boundary stays intact; no direct renderer IPC, Gateway HTTP, or Gateway WebSocket calls.
- MVP integration is advisory/explicit only: no automatic pausing, retrying, hidden correction, or tool blocking.
- Stage 2/3 schema extension fields must exist, but Stage 2/3 behavior must not be implemented.
- Production code follows TDD: write a failing test, watch it fail, then implement the minimum code.
