## 2. 数据流与 authority

- `CompressionArtifact` / `semanticAtoms` / `buildDeterministicCompressionArtifact`
  仍由 `openclaw_runtime/packages/agent-core/src/harness/compaction/compression-artifact.ts`
  持有 authority；P2 没有创建第二套 context/memory/task truth。
- `compaction-validated-pipeline.ts` 是 safeguard 内的一层 finalize/audit：
  provider / LLM / boundary 的字符串输出都经过
  `normalize -> artifact -> critical ledger comparison -> damage audit -> shadow decision`。
- `compaction-safeguard.ts` 的三个出口（provider 成功、LLM 成功、无真实对话 boundary）
  统一调用 `finalizeSafeguardCompaction`，并把 `details.artifact` 和
  `details.validatedPipeline` 写入 `compaction.details`。
- `wouldRetry` / `wouldFallback` / `wouldPreserveTurns` 只写入
  `validatedPipeline`，不改变返回 summary、不 abort、不触发新增 repair。

## 8. P2 必答

- **provider trusted bypass 是否删除**：是。
  `openclaw_runtime/src/agents/agent-hooks/compaction-safeguard.ts` provider 成功分支
  不再有 “trusted” early-return；注释改为 “provider output is still untrusted” 并调用
  `finalizeSafeguardCompaction`。测试见
  `compaction-validated-pipeline.test.ts > finalizeSafeguardCompaction (safeguard wiring)`。
- **provider 与 built-in LLM 是否真的共用 finalize**：是。
  三个出口（provider/LLM/boundary）都调用 `finalizeSafeguardCompaction`；
  测试见 `applies the same audit semantics for provider and LLM sources` 和
  `returns artifact and validatedPipeline for every safeguard exit source`。
- **`details.artifact` 是否在三个出口都生成**：是。
  `compaction-safeguard.ts` 的 boundary、provider、LLM 三处 `details` 均含
  `artifact` 与 `validatedPipeline`。
- **would\* 是否只记录未 enforce**：是。
  `buildValidatedCompactionOutput` 只返回 decision 字段，调用方只把它放进
  `details.validatedPipeline`；没有任何分支根据 `wouldRetry` /
  `wouldFallback` / `wouldPreserveTurns` 改变 summary 或触发 repair。
- **P2 是否新增模型调用**：否。
  `finalizeSafeguardCompaction` / `buildValidatedCompactionOutput` 是纯函数，
  不接收 model/provider/streamFn；测试用 `vi.fn()` 断言零调用。
- **critical ledger / exact identifier 缺失是否可被 deterministic audit 记录**：是。
  测试见 `reports a dropped critical decision and records shadow fallback decisions`、
  `records missing exact identifiers from critical atoms and recent messages`。
- **是否修改 UI/E2E**：否。
  P2 只改 runtime finalize/audit 和 docs；`CompactionArtifactViewer`、recovery 展示、
  i18n、Playwright 路径均未触碰。
