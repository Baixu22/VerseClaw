日期：2026-09-15。范围：压缩候选的工程成本筛选；生产继续 `promotionStage=shadow`。

本节点允许两种验收结论：在完整证据下符合预算，或明确判定不可放行。
无论哪种结论，都必须另有干净候选的 focused、typecheck、comms 和 Harness 记录。
成本通过不替代 TF-0074 的质量门，也不授权产品晋升。

## 冻结预算

以下是本轮确定的工程筛选上限，后续新实验必须先固定预算、再运行、再判定。
它们不是对历史实验的预注册声明，也不是已获批准的生产 SLA。

| 项目 | 上限或要求 |
| --- | --- |
| would-retry / shadow 的实际总 token 比 | ≤ 1.20 |
| would-retry / shadow 的平均端到端延迟比 | ≤ 1.50 |
| 单样本新增 provider retry | ≤ 1 |
| 完整配对样本 | 固定 manifest，至少 30 条，两臂样本集合完全相同 |
| 质量与安全 | 原有质量阈值全部保持；不得以丢失关键事实换取成本下降 |

20% token 增幅与 50% 延迟增幅是保守的候选筛选余量，用于阻止一次修复把长期成本倍增。
如需提高，须在下一轮实验前写明理由与新预算；不能为已失败的数据事后放宽门槛。
总 token 指 provider 返回的输入加输出 usage，不用字符估算、摘要长度或 evaluator token 代替。
平均延迟覆盖同一条压缩任务的首次请求、协议重试和修复请求；两臂使用相同压缩模型和设置。
货币成本须有对应价格或账单。本轮没有这类输入，不把 token 或运行时的 cost=0 写成费用结论。

## 证据要求

预算 PASS 必须绑定同一干净候选的 HEAD、tree、manifest、模型、参数和原始逐样本记录。
完整集合中任一臂缺 usage、延迟、成功结果或样本，均为证据不足；不得删去失败样本后计算 PASS。
分母必须大于零，数值必须有限且非负。provider 返回不完整的 usage 不能按零成本处理。
只记录低敏摘要与文件哈希；凭据和完整 provider payload 不进入报告。

旧报告可以支持继续不放行，不能重新签成当前源码的成功实验。

## 新增 retry 触发条件的预算

对固定配对集合，令 r 为新增触发率，c 为触发样本平均新增开销除以全部样本的 shadow 平均开销。
则新增相对开销为 r × c；token 和延迟分别计算，已有 retry 的开销也计入同一总预算。
新增规则只有在总 token 增幅 ≤ 0.20、总平均延迟增幅 ≤ 0.50 时才有成本空间。
不能因 structuralFidelity 或 goalAlignment 低于 70 就先接入新的 retry，再补预算。
缺少 r 或 c 的当前实测值时，结论仍为不可放行，不用零值填空。

累计 200 次压缩、抽检 30 条误报率或单独的质量绿灯，都不能替代以上成本条件。
本轮不改变 runtime gate、默认值、重试次数、传输层或任何产品锁。
