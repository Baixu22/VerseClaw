## 2. 数据流与 authority

- `CompressionArtifact` / `semanticAtoms` 仍由 agent-core
  `compression-artifact.ts` 持有 authority；`schemaVersion` 仍为 `1`。
- `CompressionEvidenceRef.type` 新增 `"archive"` / `"cvk"`，并同步到
  agent-core、Gateway `CompressionEvidenceRefSchema`（在既有 `Type.String()`
  基础上显式列出新字面量，保持旧 payload 兼容）、`shared/host-api/contract.ts`、
  Electron `mapSemanticAtomEvidenceRefs`（新增已知类型集合并保持 unknown -> other）。
- `compaction-addressability.ts` 是 P3 的 deterministic 检查层，不调用模型：
  - `auditCompactionAddressability` 只做确定性检查；
  - `bindCompactionArchiveEvidence` / `bindCompactionDetailsArchiveEvidence`
    把 checkpoint archive handle 回填到 critical atom evidence；
  - `buildPreviousCompactionLedgerMessage` 生成 bounded 的 atom ledger 投影。
- `compact.ts` 在 `session.compact()` 拿到 `compactionDetails` 后、持久化
  checkpoint 前调用 `bindCompactionDetailsArchiveEvidence`，使用
  `checkpointSnapshot.archiveHandle` 回填；无 handle 时保持原 details。
- `compaction-safeguard.ts` 的 `prependPreviousSummaryForRedistill` 优先使用
  `buildPreviousCompactionLedgerMessage`；无 `previousArtifact.semanticAtoms`
  时保留 legacy previousSummary 路径。
- `compression-artifact.ts` 的 `atomsToFacts` / `atomTextByType` 只使用 active
  atoms（排除 `stale` / `superseded`），但 ledger 仍保留这些 atoms。
- 未创建第二套 Context Store / Budget / Task Ledger / Memory / Task Forest。

## 8. P3 必答

- **每个 critical atom 是否都有可解析 evidence ref（给出测试名）**：
  `compaction-addressability.test.ts > does not treat a session-only critical atom as addressable`
  证明 session-only 不被当作 addressable；
  `makes every critical atom addressable after archive bind and survives JSON round-trip`
  证明 archive 回填后 `addressableCount === criticalAtomCount`。

  archive handle 在 `compact.ts` 的 `compactionDetails` 回填
  （`bindCompactionDetailsArchiveEvidence`，使用 `checkpointSnapshot.archiveHandle`）；
  file hunk 由 `CompressionEvidenceRef.type: "file"` 表示并保留在 atom evidence；
  CVK selector 由 `CompressionEvidenceRef.type: "cvk"` 表示，
  `auditCompactionAddressability` 通过 `resolveCvkSelector` 解析。

  是。`compaction-addressability.test.ts > returns missing_selector and stale_selector
  diagnostics and keeps recovery explicit-fail`，且
  `buildCvkRecoveryContext` 仍返回 `ok=false`；
  另有既有测试 `context-runtime-kit-recovery-context.test.ts > fails visibly when
  required selectors are missing` 与 `marks stale document or code refs...`。
- **后续 compaction 是否从 atom ledger + 新消息重建（给出测试名）**：
  是。`compaction-addressability.test.ts > prefers a bounded atom ledger projection
  over the previous summary` 与 `bounds ledger projection output and omits large
  atom bodies`；`compaction-safeguard.ts` 的 `prependPreviousSummaryForRedistill`
  优先使用该 ledger。
