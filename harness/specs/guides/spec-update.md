Use spec updates for lessons that should change future AI coding behavior.

Promote knowledge into:

- `rules/` when it can be validated or must never be violated.
- `layers/` when it is a subsystem convention tied to paths.
- `guides/` when it is a thinking checklist or workflow reminder.

Keep private session notes in `harness/workspace/<developer>/`. Do not commit personal journals unless the note has been distilled into a team-owned spec.
