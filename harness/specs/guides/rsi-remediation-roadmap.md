RSI 修复路线（2026-11-07）

本路线从已经封存的 216 槽 NO_GO 实验继续，先修复任务输入和执行协议，再接通经验归因与候选演进。开发按依赖顺序推进；有效改进以独立任务上的收益、安全、成本和回滚证据判定。

| 顺序 | 交付 | 依赖 | 可读回的验收结果 |
| --- | --- | --- | --- |
| 0 | 固定修复范围、节点和实验版本 | 当前源码与冻结测量 | 六个执行节点、依赖、失败分支、资源要求和原版本恢复入口完整 |
| 1 | 公开接口契约与任务上下文 | 0 | 24 个任务均有身份绑定的公开输入；声明没有实现体；缺失、截断和引用来源可验证；旧 v1/v2 请求保持原语义 |
| 2 | 有预算的工具与修复循环 | 1 | 读文件、范围内修改和公开检查有执行记录；隐藏 oracle 在终态独立运行；次数、tokens、时限、续跑和错误分类受冻结协议约束 |
| 3 | 经验采用与结果归因 | 2 | 经验 id/version 与 task/run/arm/repeat、实际采用及结果相连；检索不冒充采用；unknown、重复和无关联反馈可观察 |
| 4 | 候选版本、选择与多代演进 | 3 | training/validation 与最终 held-out 分离；至少两代候选有父子身份、归因、选择或淘汰记录；只接纳满足前置门的候选 |
| 5 | 新协议下的完整配对测量 | 2、4 | 独立实验记录任务、模型、资源和协议；完整配对、pass^k/pass@k、区间、实际用量、成本与安全结果可复算 |
| 6 | 独立裁决与行为回滚 | 5 | 独立重算收益和污染检查，执行 off/on/off；有效经验演进有证据后才更新代码自改的准入判断 |

第一段保留历史 base/reference、任务身份、split 和 oracle 字节，增加前瞻的公开输入协议 `RsiCodingTaskInputs/v1`。声明从历史公共类型和 API 投影得到，允许公开的名称、参数、返回结构与文档/CLI 契约；目标实现体、隐藏测试、评测答案和原接受记录的正文由 evaluator 保管。每一项输入都绑定来源 revision、blob 摘要和内容摘要。

`RsiCodingCollector/v3` 单独检验公开契约与上下文补齐，仍采用单次 JSON 输出。`RsiCodingCollector/v4` 再引入有界工具循环。协议分开，便于在同样的任务和候选条件下区分输入改动和执行改动的影响。原 v1/v2 批次按其冻结评估器恢复和解释。

上下文构造优先给出完整公开契约、基线目标文件和可验证的调用方信息。缺失的新模块保持 missing；其公开接口通过声明补齐。大文件和目录范围有明确清单和读取方式，所需接口不能静默截断。每个任务公开的可写范围、可读文件与检查项目分别冻结。

工具循环先复用现有 Responses provider、编辑解析器、历史 workspace 准备、独立 grader 和配对统计。工具效果只发生在独立 task workspace；路径、编辑范围和预算由执行器检查。公开语法与接口检查和最终隐藏 oracle 分离。模型不能读取隐藏测试、修改 evaluator、改变权限或用测试结果反向训练最终 held-out。

v4 的工具接口为 `read_file(path, startLine, maxLines)`、`apply_edits(edits)` 和 `check_public_contract()`。批量编辑的每一项包含 path、oldText、newText；oldText=null 写完整文件，其余情况要求唯一的精确文本匹配。这样 20 个规范文件可在一次工具调用中修改。读取范围由公开输入来源清单固定，修改范围为 task targetScope，公开检查仅验证语法与公共声明约定；最终行为判分仍由历史 oracle 执行。每槽最多 4 次 provider 调用、12 次工具调用，每次工具输出最多 12000 字符，最多修改 32 个文件且总 UTF-8 编辑内容不超过 256000 字节；初始公开输入上限为 100000 字符。单请求上限 240 秒、单 oracle 上限 300 秒，每槽 provider 阶段上限 900 秒。无 provider 重试，工具续接和原始响应逐项计入预算与收据。版本化修订记录为 plan-amendment.v2.json。

采用归因复用现有 SEKB 和角色记忆存储。一次检索只记录检索；实际采用记录来源、版本和具体 task/run，结果由执行观察或 grader 提供。反馈进入诊断和独立实验数据，经过预登记效果验证后才进入检索或保留策略。权重与策略由 evaluator 在独立变更中冻结，不依据最终 held-out 调整。

候选演进先限定在经验或 prompt。生成器读取训练数据，产出带摘要和父版本的候选；选择器仅使用训练/验证结果，最终 held-out 由独立角色封存和评估。每代保留被淘汰的候选、原失败和预算消耗。两代执行记录证明迭代路径，正收益仍由任务级配对测量判断。

新测量的最低条件保持 k=3、至少 20 个完整独立 task case、5pp 绝对改善门槛、95% 配对区间下界大于零、成本增长不超过 10%，安全和负锚点零回归。20 个 case 是最低判定条件，实际样本量还需由先导数据的方差和目标功效规划。provider、基础设施、模型和 grader 失败分别保存；预算或终态用量未知时不生成成功或成本结论。

资源在实际调用之前冻结：endpoint/model、whole-run tokens 和调用上限、单请求和单 oracle 时限、工具次数及价格依据。24 任务 × 3 臂 × 3 重复的 v4 全轮最多 864 次 provider 调用；建议 tokens 上限为 12000000，实际授权额度与价格依据在新测量前确定。已有 endpoint 与凭据可复用，凭据不进入产物。新的费用预算需要所有者的具体授权；节点实现、离线检查、agent 模拟与证据准备继续由 agent 完成。

失败分支按原因处理：接口来源缺失或漂移时停止新协议准入；工具越界或预算用尽时保留终态；实验不足或负收益时不选择该候选。工程节点只有在其产物验收完成后关闭，有效改进目标还需完整收益证据。产品默认值、发布和代码自改权限继续由现有规则决定。
